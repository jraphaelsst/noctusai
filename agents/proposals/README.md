# Agent Proposals

Unified folder for proposals generated by ALL agents. Scoped by agent name in the filename.

## Naming Convention

```
<agent>-<YYYYMMDD>-<HHMMSS>-<slug>.md
```

Examples:
```
keeper-20260416-153635-extract-criar-meta.md
reviewer-20260417-091200-missing-error-handling.md
monitor-20260418-140000-memory-leak-detected.md
```

Filter by agent: `ls agents/proposals/keeper-*`

## Proposal format

```markdown
# Proposal: Title

**Agent:** keeper
**Generated:** 2026-04-16 15:36
**Severity:** high|medium|low
**Effort:** high|medium|low
**Affected products:** product1, product2
**Status:** pending|accepted|rejected

## Problem
What's wrong and why it matters.

## Proposed Solution
Concrete steps to fix it.

## Acceptance Criteria
- [ ] All tests pass
- [ ] Keeper validates clean
```

## Lifecycle

1. Agent discovers issue → writes `<agent>-<timestamp>-<slug>.md` here
2. Human reviews → updates **Status** to `accepted` or `rejected`
3. Accepted → implement. Rejected → stays as record with reason.

## For future agent developers

```python
from agents.keeper.proposer import generate_proposal

generate_proposal(
    title="Your finding",
    problem="What's wrong",
    solution="How to fix",
    affected_products=["product-name"],
    severity="medium",
    effort="low",
    agent="your-agent-name",  # becomes the filename prefix
)
```

The `agent` parameter scopes the proposal. Deduplication works across all agents — same finding from two agents = one proposal.
