## §3 · Recommendation matrix (top 10)

Three classifications:

- **Push template forward** — template lags reality; update canonical to match
  the products. Work happens at `templates/product-seed/`; products converge
  for free.
- **Pull products back** — products drifted; re-sync each to canonical. Work
  happens at the product level; template stays as-is.
- **Genuine divergence (placeholder)** — small_drift but the divergence is
  **scaffold-time substitution by design** (`{{PRODUCT_NAME}}`,
  `{{PRODUCT_ICON}}`, `{{BACKEND_PORT}}`, `{{FRONTEND_PORT}}`,
  `{{SCHEMA_NAME}}`). The template *intentionally* differs from products. The
  audit should ideally **mask these placeholder substitutions** before
  classifying as drift — see §4 follow-up.

| # | File | Recommendation | Rationale |
|---|---|---|---|
| 1 | `frontend/index.html` | **Genuine divergence (placeholder)** | All 11 products differ on `{{PRODUCT_NAME}}` only. No real drift. |

## §4 · Recommended follow-ups (for architect/user — not actioned here)

1. **Push the template forward on `frontend/tailwind.config.ts`** — replace the
   stale inline shape with `export default createTailwindConfig();`. All 11
   products will go from `small_drift` to `identical` immediately. Highest-leverage
   single edit in the report.

2. **Teach `audit_drift` about scaffold-time placeholders.** Today the tool
   reports placeholder substitution as drift, drowning the *real* drift signal
   in noise. A small enhancement — apply a placeholder-substitution layer to the
   template text before diffing (or recognise standard `{{X}}` tokens as wildcards
   matching anything on the product side) — would change the small_drift count
   from 163 to a much smaller number that surfaces only the *interesting* drift.
   This is itself an absorption opportunity (the placeholder set is well-known:
   `PRODUCT_NAME`, `PRODUCT_ICON`, `BACKEND_PORT`, `FRONTEND_PORT`, `SCHEMA_NAME`).

3. **Audit the `large_drift` outliers separately** — files like
   `frontend/src/pages/Login.tsx` (3 large_drift products),
   `frontend/src/pages/Landing.tsx` (5 large_drift), `backend/app/config.py`
   (8 large_drift) — these are intentional per-product customisations. Worth
   reviewing whether they should remain divergent or be pulled into the template
   via named seams.

4. **Investigate the high `missing_count` (159 pairs)** — many template files
   are absent from many products. Either products were scaffolded before the
   template grew those files (template forward of products), or the products
   stripped them out (products pulled away). Either case warrants a follow-up
   audit pass with a different lens (`missing` is not `divergent` — it's
   "never inherited").
