# Council a341e383 — queue lifecycle spec (full view)

Recommendation: RECOMMENDATION: adopt the owner's intent with amendments. (1) open enqueue only when conflict-safe BY CONSTRUCTION (items 1,4,6,9 + CLAUDE.md budget check landed, ejection-by-cause fitness function); (2) steward asks ONE bounded question via the durable inbox (needs_info, TTL ~1 CI cycle), not noc-questionnaire; then fixes itself via withdraw mq + NEW rescue-<slug> branch, never patching feat/* nor handing back; (3) no timer polling: subagents hand back and end, top-level sessions check release_steward mine at checkpoints; (4) end only on a mechanical predicate from release_steward mine, cleanup via task_branch landed confirm=True as last act; (5) docs in skills/patterns + durable inbox notice, no new CLAUDE.md line.

Biggest risk: Going live on steward-fixes + end-and-salvage before the end predicate and ownership-transfer record exist: an agent salvages after 'enqueued', its entry is then ejected, the steward rescues with no source branch, and a salvage commit mid-CI cancels the awaited run; plus open enqueue before items 6/9 makes every collision a 25-min ejection the steward must fix.

First step: Land one docs-only change writing the amended spec into merge-queue.md, release-steward.md, background-agent-lifecycle.md, product-engineer.md and noc-steward, with supersession notes, not-live-until markers, a decision record and a durable inbox notice.

Amended spec + build list: see queue-lifecycle-decision.md

## Objections

- **A** (lens:expansionist, major) Lifecycle is specified for local top-level sessions on one Mac, but the next six months bring cloud sessions, more machines and in-app council/API agents: they have no 15-min local poll, no reboot-surviving peer message, and cannot be asked via SendMessage. The spec should define the agent-agnostic contract now: the durable steward inbox (release-steward.md:89-96 request/mine/status) as the single channel for clarification and outcomes, with the session as an optional subscriber, so a cloud agent or API caller works identically.
- **B** (lens:executor, major) Item 3's 15-minute polling duplicates push signals that already exist (merge-queue-watchdog.yml every 10 min, release_steward mine, noc-steward SKILL §2 Monitor feed) and spends context on every poll on an 8 GB Mac, against 'gated is not blocked'. Background subagents cannot poll across idle periods and a parent resume is free, so the spec must say standby applies only to top-level sessions and be driven by one cheap durable check (release_steward mine) or a scheduled wake, not an agent loop.
- **C** (lens:first_principles, major) Spec point 4 (end once nothing could trigger the agent; each agent salvages its own worktree) has no decider and races the steward: if the agent salvages or deletes a worktree while the steward is rescuing a later-ejected entry, the fix source vanishes, and the recorded incident shows a salvage commit mid-CI cancelled the CI being awaited ('teardown goes last'). Simplest rule: the end condition is the mechanical LANDED verdict of the last entry (from the durable record), and worktree cleanup runs only after it; an EJECTED entry keeps the branch alive until the fix lands or is explicitly withdrawn. A session also cannot close another, so 'agent' must be defined as session vs subagent; for a subagent, end plus TaskStop by the parent already exists (background-agent-lifecycle.md:10).
- **D** (lens:contrarian, major) Spec item 4 (each agent salvages own worktrees before ending, ends once nothing can trigger it) collides with item 2: an agent that salvages and ends while the steward is fixing its ejected entry destroys the worktree the fix depends on, and nothing defines who decides 'nothing could trigger me'. The recorded incident (salvage leg committing a recovery pointer mid-CI cancelled the CI) says teardown goes last, and task_branch cleanup falsely refused landed branches 11 times on rebased twins (fix unlanded). End condition must be mechanical: entry LANDED confirmed via release_steward mine, no open ejection, then salvage; and a session cannot be closed by others, so 'agent' must be defined as session vs subagent.
- **E** (lens:executor, blocker) Item 1's condition (open enqueue only if conflict-safe) is not met today: enqueue renumbers migrations against dev only (merge-queue.md:89-91; 'item 6' unbuilt) and the CLAUDE.md cap sits at 2500/2500, so two parallel enqueues collide and each ejection costs about 25 min of CI. The spec must make item 6 (allocate against open mq/* entries) plus a pre-compose overlap check on derived files the prerequisite, or the open-enqueue switch stays off; today it is only safe-by-ejection.
- **ED** (lens:first_principles, blocker) Spec point 3 (stand by, poll every 15 min) contradicts background-agent-lifecycle.md:9, which makes the hand-back the LAST act with no polling or sleep loop after it. The real need is knowing a delivery's outcome, and push signals already exist (watchdog LANDED/EJECTED, release_steward mine, commit statuses). Simplest fix: drop polling, record the requester and purpose durably in the steward inbox so the outcome is routed to whoever must act, and let the session end.
- **F** (lens:executor, major) Item 5 ships the build triad as prose only: no gate, no telemetry, and the announce channel is unspecified, while peer messages are lost on reboot and CLAUDE.md is at its 2500/2500 word cap so a new §1 line cannot land without trimming. Put the procedure in the noc-steward skill and merge-queue.md (where fresh sessions auto-trigger), add one router pointer by consolidating an existing line, deliver the announcement via the durable steward inbox plus session-start context, and add a keeper or log of ejections-by-cause and polls-per-agent to prove it works.
- **FM** (advisor:architect, major) End-and-salvage (item 4) has no mechanical end condition and races the steward: 'nothing could trigger it' is undecidable by the agent, an ejected entry the steward may rescue still needs its branch, and the recorded teardown-goes-last incident shows a mid-CI salvage commit cancelled the awaited CI.
