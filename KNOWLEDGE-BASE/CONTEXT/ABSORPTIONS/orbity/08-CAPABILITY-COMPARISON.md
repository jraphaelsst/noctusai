# 08 — Neutral Capability Comparison (Orbity ⟷ noc) + What We Can Learn

> **Directive (2026-06-02):** *don't assume they do better — neutral research on everything, then evaluate what we can learn.* This doc compares **what Orbity actually operates** against **what noc actually ships today**, on grounded evidence (read-only audits of both codebases). Verdicts cut both ways. "Learn" actions are noc-facing; where noc is already ahead, the lesson is *don't copy their weaker approach.*
>
> Evidence base: deep-dives [`09-DEEPDIVE-FINANCIAL-MANAGEMENT`](./09-DEEPDIVE-FINANCIAL-MANAGEMENT.md) · [`10-DEEPDIVE-META-ADS`](./10-DEEPDIVE-META-ADS.md) · [`11-DEEPDIVE-CHATBOT-AI-AUTOMATION`](./11-DEEPDIVE-CHATBOT-AI-AUTOMATION.md), plus the wave-1 lenses and two read-only noc-maturity audits. **Caveat:** Orbity's *live* DB (real automation flows, scoring rules, tuned prompts) is not available — we see the code, defaults, and schema, not their tuned production rows.

## Learning priorities (ranked, neutral)

**Tier 1 — clear capability gaps where Orbity is battle-tested and we're thin/absent:**
1. **Financial management** — DRE + orchestrated month-end closure + recurring/installment model + dual accrual/cash. (We have payment *fragments*, no agency-grade finance system.)
2. **Meta CAPI feedback loop + Lead-Ads pipeline** — the genuine moat; we have an *unwired* ads adapter and zero CAPI/pixel.
3. **No-code branching automation engine** — we have email-only drip + external n8n; their durable-queue flow engine is a strong seed-organ candidate.
4. **Multi-channel notifications fan-out + per-event prefs + web-push** — our weakest breadth domain.
5. **BR payment/fiscal rails** — Asaas (PIX/boleto) + Conexa (NFS-e) + dunning + reconcile-cron. Net-new.

**Tier 2 — meaningful upgrades to existing noc capabilities:**
6. Configurable lead-scoring rule engine + temperature + public lead-capture (CRM).
7. Client-approval workflow + content calendar (social).
8. BR WhatsApp 9th-digit + inbound→lead auto-promotion.
9. PWA + product-tour + white-label branding.
10. Bulk Excel import with AI column-mapping.

**Tier 3 — where noc is already equal/ahead (do NOT adopt Orbity's approach):**
- LLM/chatbot **infrastructure** (cost governance + provider abstraction) — keep ours; harvest their prompt *content*.
- E-signature (3 real providers) — keep ours; harvest their fiscal-snapshot + AI-gen prompt.
- Email-marketing ESP — keep ours.
- Public-portal **hardening** — keep ours; add their approval-action.

## Cross-cutting neutral observations
- **Several Orbity strengths are battle-tested-by-real-use** (forecast mode, anti-ghost, dunning opt-ins, prepaid-BRL balance regex, accent-folded matching) — domain depth that comes from daily operational pain, not a spec. That's the kind of knowledge the user wants preserved.
- **Several Orbity strengths carry real weaknesses** (open finance RLS, plaintext tokens, mock-data-in-prod, no webhook HMAC, abandoned PPR, snapshot-vs-live divergence). Absorbing the *intent* means re-implementing on noc's disciplined seam (RLS-via-trusted-table, encrypted creds, no silent fallbacks, contract-first), **not porting the code as-is.**
- **Several noc strengths are trapped in one product** (CRM in erp, email-marketing in social-wiring, 2-way calendar in therapy, portals in erp/therapy). The absorption is a forcing function to decide which become **shared seed organs** — and Orbity's cross-cutting versions are useful reference designs for that promotion.
