## Overview

Personal finance tracker for **organizations** — companies use it as a financial management tool, individuals use it via single-member "personal" orgs (same data model, same RLS). Multi-account transaction management, budgets, recurring transactions, investment portfolio tracking, stock watchlists with real-time quotes (yfinance), financial reports, and dashboard analytics.

## Org scoping (uniform with ERP / Therapy / AdConnect post 2026-05-03)

Every PF operational table is `org_id NOT NULL REFERENCES public.organizations(id)` + `created_by UUID NULL` audit field. RLS is uniform: `org_id = public.current_org_id()` (parents direct, child tables traverse via parent IN-subquery). No NULL branches, no PF-local helper. The platform `public.current_org_id()` reads `(auth.jwt() ->> 'org_id')::uuid` from the JWT claim.

**Personal-org bootstrap.** Solo users land in a single-member `is_personal=true` `public.organizations` row, auto-created at first-PF-login if missing via `noctusai_lib.domain.org.ensure_personal_org` (seed-shared with therapy / future products). PF wraps it in `app/services/onboarding_service.ensure_pf_personal_org` which threads the `Pessoal — {email}` template and seeds the 19 default categorias (`PF_DEFAULT_CATEGORIAS`) into the new org. Categorias are per-org seeded copies (every org owns its 19 starter rows + can rename/delete freely) — not platform globals.

History: this layout shipped via `pf-org-scoping-migration` (Phase 1+2 flipped 12 op tables from user-scoped to org-scoped 2026-05-03). Migration `001_personal_finance.sql` was rewritten in the same project to declare the deployed truth instead of the original fictional shape.

## Router Groups (14)

- **Core**: contas (multi-type accounts), transacoes, categorias, operacoes (batch import/categorize)
- **Planning**: orcamentos (budget limits per category), metas (savings/debt goals), recorrentes (salary/rent/subscriptions)
- **Investments**: carteira (portfolios), ativos (positions), watchlist (yfinance quotes), cotacoes (real-time prices), patrimonio (net worth)
- **Analytics**: dashboard (summary/charts), relatorios (monthly/category/cash flow)

## PF-Specific

**Scheduler** (`app/scheduler.py`): APScheduler processes due recurring transactions automatically, creating corresponding transacoes.

**Org ID extraction**: routers call `get_current_user_org(authorization)` from `app/dependencies.py` → `Service(db, org_id)`. Every service constructor is `__init__(self, db_client, org_id: str)`; queries filter by `org_id`; inserts populate `org_id` from the constructor and `created_by` from the current user when audit attribution matters.

**Real-DB tests**: Auto-skip when `SUPABASE_URL` or `SUPABASE_SERVICE_ROLE_KEY` not set. Use `ClientOptions(schema="personal-finance")`.
