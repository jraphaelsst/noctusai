## Members (verbatim from §1)

- **Branching-first orchestration.** Orchestrator=architect (stays with user), subagents=engineers; inline below the cutoff. → `KB § 01-PHILOSOPHY.md` · skill `noc-branch-dispatch`
- **Parallelization-first orchestration.** Real specialized-agents-in-parallel is the DEFAULT mindset (each `.claude/agents/<name>` brings its lens); serial / inline only when shared-state, single-coherent-voice, or below the inline cutoff. → `KB § PATTERNS/architect/parallelization-first-orchestration.md` · skill `noc-branch-dispatch`
- **FE↔BE contract-first dispatch — default for connected BE/FE work.** Author the endpoint contract (shapes/field-names/envelope-vs-bare/status) FIRST; both build to it. → `KB § PATTERNS/architect/fe-be-contract-first-dispatch.md`
- **Don't block on background tasks — keep working in parallel.** Idle-polling a running bash/agent burns session budget; queue independent background work + foreground docs/gates instead, consolidate on completion. → `KB § PATTERNS/common/dont-block-on-background.md`
- **Background agents end when done; peer sessions are informed, never stopped.** The hand-back is an agent's LAST act (no polling after it; name an unfinishable leftover and end); on every hand-back the leader salvages then `TaskStop`s THAT agent and takes over the leftovers; never stop another session unless the owner says so. Receiver-side: a pull hook tells a session when `origin/dev` advanced over methodology surfaces or its own claimed paths; the pusher sends HEADS-UP to live peers. → `KB § PATTERNS/common/background-agent-lifecycle.md` · `KB § PATTERNS/architect/orchestration-craft-canon.md` §6.13
- **Merge all ready slices before integrating — ONE train, ONE integrate.** Each integrate costs 30-40 min of merged-tip gates; `task_branch action=train slugs=[...]` merges the ready `feat/*` branches `--no-ff` (least-conflict-first, stop+reconcile on conflict) into a `train-<name>` branch, narrow-tests the overlap files, then a single `integrate` lands all and cleans every rider; serial integrate only for a lone branch or hotfix. → `KB § PATTERNS/architect/branching-dispatch.md §6b`
- **Dispatch via `task_branch`, NEVER Agent `isolation: "worktree"`.** 🔴 Agent isolation forks from an arbitrary base (NOT `origin/dev`) — stale-base bug. Two-level: self-branch off `origin/dev` → `task_branch action=start` per engineer → dispatch in. → `KB § PATTERNS/architect/parallelization-first-orchestration.md`
- **Inline = empersonate; don't over-inline.** Inline-dev in the specialist's lens (discipline + owns_kb); orchestrator leverage = fan-out — serial inline bulk-build is slow + incomplete; break big modules into dispatches, 3rd inline build step ⇒ dispatch. → `KB § PATTERNS/architect/parallelization-first-orchestration.md`
- **Lenses-applied commit trailer (optional).** Inline-deved commits carry a `Lenses: <name>` trailer → auditable via `git log --grep "Lenses:"`. → `KB § PATTERNS/common/lenses-applied-trailer.md`
- **Wave-based dispatch + collision-class.** Merge cleanliness is decided at DISPATCH (C1/C2/C3), not at merge. → `KB § PATTERNS/architect/branching-and-merging.md §18/§21`
- **Dispatch with PROJECT — return with notes.** Tech-lead writes PROJECT.md §4a routing before dispatch; engineer/inline-lens returns a `delivery` note, or a `surface` note + BLOCK when re-routing mid-flight. → `KB § PATTERNS/common/dispatch-with-project-and-notes.md`
- **Hardware admission bounds parallel-by-default.** Heavy runs (suites/vitest/e2e/vite build/merged-tip gates) take a machine-wide slot admitted on MEASURED capacity (CPU idle ∧ reclaimable memory ∧ swap-out, per-host phase in `deploy/fleet/hardware-budget.json`); not admitted ⇒ not run (`waiting_for_slot`, overloaded ⇒ hold, re-check on the adaptive timer. Enforced at the first expensive consequence: the `heavy-run` PreToolUse guard (`claude-guard-heavy-run.py`) denies an ungated pytest/vitest/playwright/vite-build Bash call and prints the wrapped command. → `KB § PATTERNS/devops/hardware-admission-budget.md`
- **One elected CI/deploy steward per machine — gated is not blocked.** ONE leader session (interactive, top-level — never a dispatched subagent; its own subagents act under its lease) holds the CI/deploy role: enqueue, `landed`, bless, promote, deploy, prod migrations. Before any queue/deploy action every session checks its environment (`ListAgents` + `release_steward action=status`); with no steward the leader that has shipping work `claim`s and ANNOUNCES to every peer (`SendMessage`), and reports `LANDED <dev sha>` / `EJECTED <reason>` / `DEPLOYED` back. A non-holder is refused by the `release-steward` PreToolUse hook (names the holder; override = `NOC_STEWARD_OVERRIDE=<reason ≥10 chars>`, logged) and the tool backstop — it files its delivery with `release_steward action=request slug=<slug>` (latest `head_sha` wins) and KEEPS BUILDING, never waits; the steward drains the whole outbox in one batched pass. Messages are sugar — the outbox + the hook are the record (SendMessage can fail for idle peers). Sequencing (a migration before its image) is the steward's call. → `KB § PATTERNS/devops/release-steward.md` · skills `noc-ship` · `noc-self-branch`

- **Queue lifecycle — ask once, fix by rescue, end clean.** The dev-queue steward resolves an ejection: ONE batched `noc-questionnaire` peer-mode question to the requester's ROLE (owner fallback, TTL ≈ one CI cycle); a live, not-done requester that answers "already fixing" keeps it, else the steward withdraws `mq/*` and dispatches a rescue engineer on a NEW `rescue-<slug>` (never patches `feat/*`, never hands work back to a done agent). Subagents hand back and end; top-level sessions with a pending delivery check `release_steward mine` every 15 min; a session ends only when the end predicate is true, salvaging its own worktrees as the last act. Each point goes live on its build marker. → `KB § PATTERNS/devops/merge-queue.md` §3–§4 · `KB § PATTERNS/devops/release-steward.md` §7a · `KB § PATTERNS/common/background-agent-lifecycle.md`
- **Team of teams — positions up, common ground down.** One tree deployer; many self-managing teams, one orchestrator each, its single outward voice. When agents of any role and any number must settle something, each evaluates the grounds on its own, sends a position report to the manager (the orchestrator of the smallest team holding all parties; one level up when it is a party), waits on that matter only, and continues on the manager's recorded common ground. Any orchestrator may propose improvements anywhere in the tree; the owning team's orchestrator deals with it (accepted/adapted/rejected) or passes it on (`forwarded`, destination named) — never "noted". → `KB § PATTERNS/architect/team-of-teams.md`

## Why a family line

These 14 rules shared one framework, and a session that needs one of them typically needs the rest — so a single router hop costs a lookup and returns 13 always-on lines of budget. The forcing function is the router keeper's rule-COUNT ceiling; the procedure is `/gc` step 5. → `KB § PATTERNS/common/claude-md-router-discipline.md`
