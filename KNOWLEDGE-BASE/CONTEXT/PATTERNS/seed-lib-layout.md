# Seed-lib layout

Single source of truth for the structural layout of `seed/backend/lib/noctusai_lib/`. Tells a fresh agent *where to put a new helper* and *where to find an existing one* without grepping. Replaces the implicit "everything goes at the top level until it grows" convention that had `noctusai_lib/` accumulating 26 sibling entries by 2026-04-30.

## The 6 layers

The seed-lib is split into six top-level namespaces. Each has a contract — a one-line "what belongs here, what doesn't" — and a dependency direction. Code may only import from layers BELOW it; nothing imports from layers above.

```
                ┌─────────────────────────────────┐
                │  api/        FastAPI surface    │
                ├─────────────────────────────────┤
                │  domain/     Business policy    │
                ├─────────────────────────────────┤
                │  integrations/  External SDKs   │
                ├─────────────────────────────────┤
                │  testing/    Test infra         │
                ├─────────────────────────────────┤
                │  config/     App config + secrets│
                ├─────────────────────────────────┤
                │  primitives/ Pure stdlib helpers│
                └─────────────────────────────────┘
                         imports go DOWN
```

| Layer | What belongs | What does NOT belong | May import from |
|---|---|---|---|
| **`primitives/`** | Pure functions, dataclasses. Stateless. Stdlib-only. No HTTP, no DB, no domain knowledge. | Anything that touches the network, the DB, FastAPI, Supabase, our schemas, or product-specific shapes. | (nothing in `noctusai_lib`) |
| **`config/`** | App configuration + secrets resolution. Read at startup, immutable thereafter. | Domain logic; business rules; long-lived state; version metadata (lives at the seed-lib root for bootstrap reasons). | `primitives/` |
| **`testing/`** | Mock builders, schema cache, pytest plugin, assertion helpers. Imported by product test files only. | Anything that ships in production. | `primitives/`, `integrations/` (for boundary mocks), `domain/` (for binding test mocks to deps) |
| **`integrations/`** | One folder per external service. Wraps the SDK; exposes a stable internal API. | Domain logic; rule enforcement; HTTP routing. | `primitives/`, `config/` |
| **`domain/`** | Platform-wide business primitives (notifications, invitations, audit logs, AI consent, gamification). Each is product-agnostic — every product is a potential consumer. | Single-product code (lives in `products/<x>/app/`); FastAPI handlers; raw SDK calls. | `primitives/`, `config/`, `integrations/` |
| **`api/`** | FastAPI middleware, dependency factories, mounted routers, request/response shapes. Everything above the request boundary. | Business logic; SDK details; cross-cutting helpers. | `primitives/`, `config/`, `integrations/`, `domain/` |

### What stays at the top level

Five things stay outside the layered model and live at `noctusai_lib/` directly:

- **`__init__.py`** — package barrel, lazy-loads heavy public attrs via PEP 562 `__getattr__`.
- **`logging_config.py`** — single setup hook. Called once at startup by `create_product_app(...)` (backend) and `auto_configure_for_cli(...)` (CLI / MCP). Living at the root makes it impossible to miss.
- **`_version.py`** — runtime resolver that reads `_version_static.py` first, falls back to live git. Bootstrap-time critical; loads before logging is configured.
- **`_version_static.py`** — auto-generated by `scripts/stamp-seed-version.sh`. Hardcoded paths in the stamp script + `mcp/noctusai/tools/compliance.py` detector reference this exact location; moving it would require coordinated patches across 3 systems for negligible layout payoff.
- **Transitional shims** — every old top-level path that has moved into a layer leaves behind a one-line shim like `from noctusai_lib.api.auth import *  # noqa: F401, F403`. Shims drop in the post-migration cleanup commit (step 3); until then they let products import either the old or the new path.

## Where to put a new helper — decision tree

When you're about to add a helper to `noctusai_lib/`:

1. **Does it touch the network, the DB, or an external SDK?**
   YES → `integrations/<service>/` (create the folder if it's a new service).
   NO → continue.

2. **Does it know about FastAPI requests, our HTTP shape, or middleware?**
   YES → `api/`.
   NO → continue.

3. **Does it encode a platform-wide business rule (notifications, invitations, audit, AI consent, gamification)?**
   YES → `domain/<feature>/` (folder once it grows past a single file).
   NO → continue.

4. **Is it test infrastructure (mocks, fixtures, assertion helpers)?**
   YES → `testing/`.
   NO → continue.

5. **Is it config / secrets / version metadata?**
   YES → `config/`.
   NO → continue.

6. **Is it a stateless pure function that any layer might call?**
   YES → `primitives/`.
   NO → re-read the question. By construction one of 1–6 fits, or the helper isn't general enough to live in seed lib at all (push it back to a product).

## Where to look for an existing helper

| If you're looking for | Look in |
|---|---|
| HTTP middleware / auth dep factories / role checks | `api/` |
| Notification dispatch / invite token lifecycle / audit logging | `domain/` |
| AI consent enforcement / clinical-text policy | `domain/ai/` |
| Multi-provider LLM client / cost tracking | `integrations/llm/` |
| Email digest / Resend wrapper | `integrations/email/` |
| Supabase client factories | `integrations/database` |
| Mock Supabase / `MockSupabaseClient` / assertion helpers | `testing/` |
| Pure parsers / formatters | `primitives/parsing.py` |
| Wallclock / current period reference / `frozen_time` | `primitives/timeutil.py` |
| Role constants + predicates | `primitives/roles.py` |
| App settings / secrets / version stamps | `config/` |
| The single logging entry-point | top-level `logging_config.py` |

When the table doesn't help, `noctusai_lib/<layer>/__init__.py` carries the layer's planned/active inventory in its docstring — read that first.

## Folder vs. file decision

Each layer holds either flat `.py` files or sub-folders. Use **a folder** when:

- The feature has more than one file's worth of code (~150+ lines).
- Multiple shapes emerge (e.g. `llm/chat.py`, `llm/embeddings.py`, `llm/audio.py`, `llm/budget.py`, `llm/cache.py`).
- Tests for the feature warrant their own block in `seed/backend/lib/tests/`.

Use **a flat file** when:

- The feature is one cohesive set of helpers (e.g. `parsing.py`, `responses.py`).
- It's been stable at one file for 3+ months.

A flat file may be promoted to a folder later — the feature's public API stays the same as long as the `__init__.py` re-exports the same names. This is the same approach we used for `llm/` and `email/`.

## Adding a new service to `integrations/`

When wrapping a new external SDK (Stripe, WhatsApp, etc.):

1. Create `integrations/<service>/`.
2. Inside, the public surface is in `__init__.py` — products import `from noctusai_lib.integrations.<service> import <thing>`, never the underlying SDK directly.
3. If the service has a complex multi-file shape (LLM-style: chat + embeddings + audio + budget + cache), use sub-files; the `__init__.py` re-exports.
4. Mock builders for the service go in `testing/` (NOT in `integrations/<service>/`) so production code doesn't accidentally import the test fixture.

## Adding a new domain feature

When extracting cross-product business logic to `domain/`:

1. The feature must already recur at N≥2 across products (recurrence rule). One-product features stay in the product.
2. Single-file shape: `domain/<feature>.py`. Multi-file: `domain/<feature>/`.
3. The feature's `__init__.py` exports the public surface; product code imports `from noctusai_lib.domain.<feature> import <thing>`.
4. Tests live in `seed/backend/lib/tests/test_<feature>.py`.

## Migration history

The layered model was adopted **2026-04-30** (during Phase 4 of `execution-workflow-codequality-rollout`). The seed-lib root had grown to 26 sibling entries (10 folders + 16 modules) — a flat namespace where a fresh agent couldn't tell a "platform primitive" from a "feature module" by sight.

**Rollout in 3 steps — all complete (2026-04-30):**

1. **Scaffold + doc-first** *(2026-04-30)* ✅ — created empty `primitives/`, `api/`, `domain/`, `domain/ai/`, `integrations/` folders with planned-occupants docstrings; wrote this KB doc.
2. **Move modules + add shim re-exports** *(2026-04-30)* ✅ — each old top-level module became a one-line shim like `from noctusai_lib.api.auth import *  # noqa: F401, F403` so product imports kept working unchanged. Full test suite stayed 100%-green.
3. **Update product imports + delete shims** *(2026-04-30)* ✅ — done in `projects/seed-lib-shim-cleanup/` (closed). 96 product files + 11 mcp files + the seed-lib's own framework + tests rewritten via sed. 18 shims deleted (15 `.py` + 3 folder shims `ai/`, `email/`, `llm/`). One layer-direction violation discovered + fixed during the sweep: `roles.py` was placed at `api/roles.py` in Step 2 but is pure constants, imported by `domain/page_status.py` — moved to `primitives/roles.py` (correct placement). Final test sweep: seed-lib 220, all 8 products 4,462, MCP 404 = 5,086 tests pass.

**Migration gotchas captured during Step 3** (for future agents doing similar large-scale import migrations):

- **Three import shapes** must all be rewritten: `from noctusai_lib.X import Y`, `import noctusai_lib.X`, and `from noctusai_lib import X as alias` (sub-module-as-attribute form). The third is the one easy to miss — it shows up when the test does `from noctusai_lib import credentials as creds` and patches the module attribute. After shim deletion the form fails because the sub-module is no longer reachable as an attribute of the package.
- **String-literal references** count too. `mock.patch("noctusai_lib.llm.transcribe_audio", ...)` and `caplog.set_level(..., logger="noctusai_lib.llm.chat")` are both runtime-resolved. Sed needs a second pass over quoted module paths.
- **Wipe `__pycache__` after deleting modules.** Stale `.pyc` files for the deleted shims can be loaded if their source-hash invalidation isn't perfect, masking import errors that should fire immediately.
- **Inside-out order pays off.** Fixing seed-lib's own internal references first (so the lib stops dog-fooding deprecated paths) catches layer-direction violations that the shims masked.

The shims acted as the safety net during the transition — products opted into the new paths at their own pace, no big-bang import update was required.

## Anti-patterns this layout prevents

- **"Just one more top-level module"** — every new helper had to share the same flat namespace. Now there's a clear destination.
- **Cross-layer cycles** — `auth.py` (api) accidentally importing `notifications.py` (domain) creates a cycle when notifications imports auth back. The dependency-direction rule blocks this at review time.
- **"Where does this live?" hunting** — `git grep` was the only way to find related helpers. Now the directory shows the relationship.
- **Test infra leaking into production** — mock builders next to real clients invited accidental imports. `testing/` segregates them.
