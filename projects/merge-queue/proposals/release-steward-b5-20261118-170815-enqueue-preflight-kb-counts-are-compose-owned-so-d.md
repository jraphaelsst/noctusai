## Problem

The `deliverable(branch)` preflight, item 4 `derived_current` (`task_branch.py` enqueue docstring, near line 3199), refuses a branch whose KB counts in `KNOWLEDGE-BASE/CONTEXT/02-LANDSCAPE.md` are stale at its head.

Those counts go stale on every landing. Any branch that waits while another lands is refused, even though nothing in it is wrong.

Evidence from the 2026-11-18 drain: julia-portal-openers, sw-onboarding-staff-channel and imobshotai-fe were each refused for `derived_current: kb-counts` and nothing else. Each cost a regenerate commit, a push, a full branch CI rerun (about 30 to 40 minutes) and a re-enqueue.

## Why counting earlier cannot fix it

1. A counts commit is a new head. `scoped_green` needs CI on that exact sha, so every recount means another CI round.
2. Counts made at enqueue time are stale again as soon as an earlier queue entry lands.
3. The queue already owns the counts. Its kb-counts merge driver re-renders them at compose: the `chore(kb-counts): regenerate derived counts at compose [auto]` commits on dev, and `_content_on_dev` Proof 3 in `task_branch.py`. What lands on dev is correct whatever the branch carried.

## Proposed change

In the item 4 `derived_current` check, treat the kb-counts artifacts (the paths from `_benign_stash._kb_counts_regenerated_rel_paths`) as compose-owned and report them as `compose_owned`, not `stale`. Keep refusing on every other derived artifact (`cli.py --help`, lockfiles, baselines and so on).

This amends the council 09340534 contract item "derived files regenerated" for this one artifact, for the reason above. Every other derived file still has to be regenerated by the branch.

## Tests (red first)

- A branch whose only staleness is kb-counts is queued, and the result names kb-counts as `compose_owned`.
- A branch with a stale non-kb-counts derived artifact is still refused with `needs_resync`.
- Compose still produces correct counts on dev when two branches each carry stale counts.

## Telemetry

Count `derived_current` refusals by artifact. Once this lands, kb-counts refusals should drop to zero.
