## Errors / Mistakes / Slips

- **2026-05-04 (architect, Phase 0 prep):** Asked user permission to commit at phase gate. Slip: the no-auto-commit rule was *retired* 2026-05-03 — "DO commit at phase gates without asking" is the rule. Fixed by amending `MEMORY.md` index entry to flip the framing ("DEFAULT IS commit at gates" instead of "default never; carve-outs:..."). Pre-existing memory file content was already correct — the index hook was the misleading line.

- **2026-05-04 (Engineer C, Phase 1.4 prep):** Initial test draft used `monkeypatch.setattr(sm, "PRODUCTS_DIR", tmp_path)` to redirect path resolution. Caught mid-write — patching our own module's binding sits on the *border* of the no-monkeypatch rule (it's a config knob, not a behavioral guard, so technically defensible) but the right shape is dependency injection. Refactored to add an optional `products_dir: Path | None = None` argument to `scaffold_migration()`; tests pass it explicitly; MCP tool registration leaves it None so the seed-aware default wins. Net result: zero monkey-patching of our own module, still hermetic, simpler signature for testers, and a clean function-arg seam if other callers ever need to drive scaffolding from a non-default workspace. Lesson: when path-aware tools want hermetic tests, prefer Path-arg injection over module-binding monkey-patching even when the rule technically allows it — the `products_dir=` knob is *also* a useful affordance for the (future) "scaffold migration in template workspace" use case.

## Lessons

- **2026-05-04 (Phase 1.1):** Pre-existing email-module tests use `monkeypatch.setattr(digest_module, "_post_to_resend", ...)` which patches our own internal function name — the no-monkeypatch rule's exact anti-pattern. The module pre-dates the rule (2026-04-25). New SMTP tests patch at `smtplib.SMTP` / `SMTP_SSL` boundary directly (external-service carve-out), which is correct. Lesson: when extending a flat-shape module, tests inherit pre-rule patterns by gravity unless explicitly broken; called out in §findings instead of fixing in-scope.

- **2026-05-04 (Engineer C, Phase 1.4):** Mirroring `scaffold.py`'s pattern revealed the *settings-import indirection* makes hermetic tests hard at first glance. `scaffold.py`'s tests work against the real repo (creating + deleting `products/test-scaffold-temp/`); for `scaffold_migration` we want fully tmp_path-based tests because the tool doesn't need a full product template — just a few stub `001_seed.sql` files. Lesson: when a sibling tool can be tested hermetically while the original couldn't, *it should be*. The `products_dir=` injection seam is a permanent affordance, not just test scaffolding — surfaces a future "scaffold migration in N=2 sibling workspaces" use case for free.

- **2026-05-04 (Engineer C, Phase 1.4):** N=2 keeper-detector-style integration tests now exist for sql_templates drift — `test_scaffold.py::TestSqlTemplatesIntegration` (created 2026-05-03) + `test_scaffold_migration.py::TestSqlTemplatesIntegration` (today). Both assert `set_search_path()` / `updated_at_function()` / `updated_at_trigger()` / `rls_subquery_policy()` outputs appear verbatim (whitespace-normalized) in the scaffolded SQL. **Recurrence rule fires at N=2** — triage time. Recommendation: extract the keeper-style integration assertion shape into a small shared helper (e.g. `mcp/noctusai/tests/_sql_templates_assertions.py` exposing `assert_sql_helper_in_body(body, helper_output)`) so the N=3 (next migration-emitting tool, or a `scaffold_migration_addsuffix` variant) consumes the helper. Filed as a follow-up *Improvement* below — not applied inline because the right destination depends on whether more SQL-emitting tools land in Phase 2/3 (the helper's home moves with the consumer count). Architect to triage at Phase 1 close.

## Knowledge pieces

- **2026-05-04:** SMTP via stdlib `smtplib` (sync) wraps cleanly with `asyncio.to_thread` to preserve the `async def send_digest(...)` signature without adding `aiosmtplib` as a dependency. Multipart/alternative is `MIMEMultipart("alternative")` + plain `MIMEText` then html `MIMEText` (order matters — most preferred renderer LAST, per RFC 2046).
- **2026-05-04:** SMTP security modes that matter: `ssl` (port 465, implicit TLS, `smtplib.SMTP_SSL`), `starttls` (port 587, explicit upgrade, `smtplib.SMTP` + `.starttls()`), `none` (port 25, plain — only useful for `aiosmtpd` test servers). Default `starttls` covers ~all modern providers.
