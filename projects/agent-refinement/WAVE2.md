> Base: `feat/agent-refinement` AFTER all of Wave 1 is merged (each slice reads the
> refined agents as the house shape to imitate — `frontend-engineer.md`,
> `backend-engineer.md`, `devops-engineer.md` are the executor models; `accountant.md`,
> `security.md` the advisor models). PROJECT.md §3 standards apply unchanged.

## Shared rules for every Wave-2 slice

- Files: `.claude/agents/<new>.md` + the new canon doc(s) under the named
  `PATTERNS/<domain>/` dir + additive `KB § INDEX.md` rows. Nothing else, EXCEPT
  the explicitly named extra file(s) in the hire's row.
- **No ownership transfers.** The donor agents' `owns_kb` are edited by the
  tech-lead in Wave 3 (several hires take docs from the same donor ⇒ collision).
  Each slice RETURNS a "Transfers requested" table: `doc path · from agent · why`.
- If a pre-commit keeper refuses a new agent without a roster entry (CLAUDE.md §2 /
  CONTEXTUALIZE.md §4 / 06-AGENTS.md / dev-team.md), make the minimal ADDITIVE
  roster edit (one name on the existing line/table) — the tech-lead reconciles.
- The new agent's research is YOURS (no audit exists): use WebSearch/WebFetch,
  primary sources first, every cited URL fetched. Ground every house claim in
  file:line you opened. Cache-first discovery (`noctus.dev.kb_search` / `code_search`
  / `memory_search`, `noctus.graph.*`).
- Frontmatter: `name`, `description` (role + ADVISOR/EXECUTOR + routing triggers),
  `tools` (least privilege), `model`, `owns_kb`. Executors carry the engineer-seed
  protocol line and the same verbatim "Commit ownership" block the other executors
  carry (copy it, don't reword — merge-flow zone).
- Return: engineer-seed short form + transfers requested + roster edits made +
  line counts + unverified sources + `interpretation:`.
