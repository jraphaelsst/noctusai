# 09 — Personal Finance Frontend Context

> Path: `products/personal-finance/frontend/src/`
> Dev server: Vite on port **8090**
> API target: `VITE_BACKEND_API_URL` (default: `http://localhost:8002`)

---

## Overview

Personal finance tracker frontend with 18 lazy-loaded pages, 14 TanStack Query hooks, Zustand auth store, and shadcn/ui components. All routes are protected behind auth. The Supabase client uses `db: { schema: 'personal-finance' }` so all direct `.from()` calls target the personal-finance schema.

---

## State Management

| Layer | Technology | Scope |
|-------|-----------|-------|
| Server state | TanStack Query (via hooks) | All API data |
| Global UI state | Zustand | Auth |
| Form state | React useState | Modals/dialogs |
| Session state | Supabase Auth | Login/signup/token |

### Zustand Stores

| Store | Persistence | Key State |
|-------|-------------|-----------|
| `authStore.ts` | None (managed by AuthProvider) | `user`, `isInitialized`, `setUser()`, `setInitialized()` |

**Date fields in stores use `string | undefined` (ISO strings), not `Date` objects.** Convert at component boundaries:
- Calendar `selected`: `selected={dataInicio ? new Date(dataInicio) : undefined}`
- Calendar `onSelect`: `onSelect={(date) => setDataInicio(date?.toISOString())}`

## Hook Quality Patterns (Mandatory)

### Auth Guards
Every query hook that fetches user-scoped data must include `enabled: !!user`:
```typescript
const { data } = useQuery({
  queryKey: ["contas", user?.id],
  queryFn: () => api.get("/api/contas"),
  enabled: !!user,
});
```

### staleTime Guidelines
| Data Type | staleTime | Examples |
|-----------|-----------|---------|
| Reference data (rarely changes) | 10-30 min | categorias |
| Active working data | 3-5 min | contas, orcamentos, metas, carteiras |
| Real-time-ish data | 30s-2 min | cotacoes, watchlist quotes |
| Expensive aggregations | 5 min | dashboard, patrimonio, relatorios |

### Mutation Invalidations
Every mutation must invalidate all affected query keys. Cross-entity invalidations are critical:
```typescript
onSuccess: () => {
  queryClient.invalidateQueries({ queryKey: ["transacoes"] });
  queryClient.invalidateQueries({ queryKey: ["contas"] });  // Creating a transaction affects account balance
  queryClient.invalidateQueries({ queryKey: ["dashboard"] });  // Dashboard totals change too
}
```

## Auth Initialization Pattern

`AuthProvider` calls `setInitialized()` on `authStore` after `getSession()` resolves. `AppContent` in `App.tsx` shows `<Skeleton />` while `!isInitialized`, preventing the login form from flashing briefly before the session loads.

```typescript
// AppContent
const { user, isInitialized } = useAuthStore();
if (!isInitialized) return <Skeleton />;
if (!user) return <LoginForm />;
return <AuthenticatedRoutes />;
```

## API Client (`lib/api-client.ts`)

- Uses shared `createApiClient` factory from `@shared/api`
- Auto-includes Bearer token from Supabase session
- Methods: `get()`, `post()`, `patch()`, `delete()`
- Base URL: `VITE_BACKEND_API_URL` (default `http://localhost:8002`)
- All methods use `safeFetch()` wrapper (catches network errors with user-friendly Portuguese message)
- Handles HTTP 204 No Content (returns `null`, no `.json()` call)
- Body params typed as `unknown` (not `any`) for type safety

## Date & Timezone Patterns

Same patterns as ERP. All date handling uses **America/Sao_Paulo** timezone. The server is the source of truth for dates.

### Utilities (`src/lib/utils.ts`)

Uses shared utilities from `@shared/utils`:
```typescript
formatDate(dateString: string, includeTime?: boolean): string
// "2025-10-25T14:30:00Z" → "25/10/2025" or "25/10/2025 as 14:30"

formatCurrency(value: number): string
// 1500.50 → "R$ 1.500,50"

getTodayAtMidnight(): Date    // Current date at 00:00:00 for filters
stripTime(date: Date): Date   // Remove time component
```

### Anti-Patterns

- Do NOT use `new Date()` for date comparisons (use server-computed fields)
- Do NOT convert timezones in the frontend (trust the server)
- Do NOT duplicate date logic locally (use database-calculated fields)
