# 08 — Personal Finance Backend Context

> Path: `products/personal-finance/backend/app/`
> Server: FastAPI on port **8002**
> Tests: `products/personal-finance/backend/tests/` (27 test files, 465 tests)
> Schema: `personal-finance` (via `ClientOptions(schema="personal-finance")`)

---

## Overview

Personal finance tracker backend with 15 routers and 13 services. Handles multi-account transaction management, budgets, recurring transactions, investment portfolio tracking, stock watchlists with real-time quotes (yfinance), financial reports, and dashboard analytics. All data is scoped to the user's organization via Supabase RLS.

## Exception Handling

Same handler stack as Core and ERP: `AppException` hierarchy, `HTTPException`, `ValidationError`, `PostgRESTError` (PGRST116 -> 404), generic fallback. Includes `CorrelationIdMiddleware` and `RequestLoggingMiddleware` from the shared package.

---

## Auth Pattern

Same as Core and ERP: `authorization: Optional[str] = Header(None)` -> `get_current_user(authorization)` -> `(user, token)`.

SSO flow: Core platform issues SSO token -> PF validates via `/api/sso/validate` -> creates local session.

**Org ID extraction**: Use `get_org_id(user)` from `dependencies.py` -- never inline `user.user_metadata.get("org_id")`. Raises 400 if missing.

## Router Patterns

### DELETE Pre-checks
All DELETE endpoints verify the record exists before attempting deletion:
```python
check = db.table("x").select("id").eq("id", entity_id).execute()
if not check.data:
    raise HTTPException(status_code=404, detail="Entidade nao encontrada")
db.table("x").delete().eq("id", entity_id).execute()
```

### Server-side Search
List endpoints with a `busca` query param apply `.or_()` with `ilike` for server-side filtering BEFORE pagination:
```python
if busca:
    query = query.or_(f"descricao.ilike.%{busca}%,nome.ilike.%{busca}%")
    count_query = count_query.or_(...)
```

### Router -> Service Delegation
Business logic belongs in services, not routers. Routers are thin: auth + validation + delegation.
- `dashboard.py` -> `DashboardService` for aggregation
- `relatorios.py` -> `relatorios_service` for report generation
- `recorrentes.py` -> `recorrentes_service` for scheduling logic

### Test Patterns

- **DELETE tests**: Must provide mock data with matching ID so the pre-check passes. Add a separate `test_delete_not_found` that sets empty data and expects 404.
- **Search tests**: Mock `.or_()` doesn't filter -- tests verify the endpoint accepts `busca` param and returns 200, not the filtered count.
- **Mock builder**: `MockSelectBuilder` supports `.or_()`, `.gte()`, `.lte()`, `.ilike()` etc. as no-op chainable methods (return self without filtering).
- **Real-DB tests**: Auto-skip when `SUPABASE_URL` or `SUPABASE_SERVICE_ROLE_KEY` are not set. Use `ClientOptions(schema="personal-finance")` for schema targeting.
