# CLAUDE/frontend.md — frontend behavioral rules

> **Loading discipline.** This file is not auto-loaded. Read it when starting frontend code work — the §3 routing table in `CLAUDE.md` is the canonical signal. Sibling of `CLAUDE.md`, NOT depth (depth lives in `KNOWLEDGE-BASE/`).

## Rules

- **Mockups never gate a build.** UI starts right away on the noc pattern (seed tokens, app shell), contract-first, on REAL data where it exists (sample only where it does not, labelled). A mockup is made only when the owner asks; refinements land in-flight or later + redeploy (owner, 2026-11-11, supersedes 2026-11-04). → `KB § PATTERNS/frontend/prototype-on-real-data.md`
- **Componentize everything.** Check `KB § 04-SHARED-LIBRARY.md` before writing anything new. If another product will need it, build it shared from day one — don't fork. → `KB § 04-SHARED-LIBRARY.md`
- **Gamification is subtle.** Rankings, points, progress bars — discrete; with a ⓘ icon explaining the formula; tied to real business activity (never "logged in today"-style rewards). → `KB § 07-GAMIFICATION.md`
- **Core-URL routing is MANDATORY via the seed getter.** Any product→core link (SSO callback, "back to dashboard" nav, product→core XHR) resolves core's URL through `env.CORE_URL` / `env.CORE_API_URL` (`import { env } from "@noctusai/lib"`). **Never** hand-roll `import.meta.env.VITE_CORE_* || "<literal>"` — the bare-`localhost` default is the SSO "Failed to fetch" / stale-`5173`-nav recurrence (N≥3, prod outage). The `check_handrolled_core_url` keeper blocks it (carve-out: core's own same-origin `lib/api.ts`). → `KB § PATTERNS/frontend/core-url-routing.md`
- **A product always ships a REAL icon — never render an icon NAME as text.** Render a product's `icone` through the `ProductIcon` component (`core/frontend/src/lib/product-icon.tsx`), never inline as `{product.icone}` text. `ICONS` there is the single allowlist of values that render as an SVG; an unregistered ASCII name renders as bare TEXT (the "Sprout" bug, 2026-05-25) — `ProductIcon` falls back to the `Box` icon, and a NEW product icon must be added to `ICONS` (import from lucide-react). `icone` is required + non-empty at the create API (`ProductCreate.icone: Field(min_length=1)`). The `check_product_icon_registered` keeper folds the core product-catalog migrations and flags any live product whose seeded `icone` is empty or not in `ICONS` (emoji allowed). → `KB § PATTERNS/frontend/product-icon-registry.md`
- **Sidebar nav groups start closed by construction — never add a per-group "open by default".** The canonical `Sidebar` organ ignores `NavGroup.defaultOpen`; only the active-route group auto-expands, and the rest is a user's persisted (localStorage) choice. → `KB § PATTERNS/frontend/frontend.md`
- **noctusai.com website = core's `src/website/` — read its docs before touching it.** Design + tech guide at `products/core/frontend/src/website/docs/` (in-app: Website → Documentação). Higgsfield MCP is website-only and needs explicit owner permission per use; not connected ⇒ don't do that work. → `KB § CONTEXT/PRODUCTS/core/WEBSITE.md`
- **A mutation writes what it knows into the cache — never invalidate-only.** Use `useCacheWriteMutation` (`@noctusai/lib/cache-writes`): draw optimistically when the result is predictable, commit the server's answer on success, then background-invalidate. Invalidate-only = write + full refetch before the screen agrees with the toast (orbity note ~2 s, 2026-10-21). Keeper `check_mutation_invalidate_only` (ratchet). → `KB § PATTERNS/frontend/mutation-cache-writes.md`
- **Mirror + owned overlay — a UI over external data declares each field's source and CRUD verbs.** Mirror (Vista) fields are read-only with a `SourceBadge` (provenance + freshness), never a dead edit button; owned fields get full CRUD through the existing service; a sync never overwrites owned data; where ours differs show both (`MirrorOverrideValue`). 8-step checklist for new UIs. → `KB § PATTERNS/frontend/mirror-owned-overlay.md`
- **A refusal is never silent.** A failed query never reaches its empty / "Cadastrar novo" branch (decide `q.isError && !q.data` first — `QueryErrorState`); every upload goes through `useUploadDocumento` + `<UploadErro>` (`@noctusai/lib/upload-refusal`) and an `onUpload` prop returns the promise (`mutateAsync`), never `void`. F75b/F76/F78/F86 (2026-10-24). Keeper `check_silent_refusal` (blocking). → `KB § PATTERNS/frontend/silent-refusal.md`
