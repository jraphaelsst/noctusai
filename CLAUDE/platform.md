## Rules

- **MCP toolkit reviews after every change (observation-only).** `python mcp/noctusai/cli.py --review` after modifying code. Detects compliance issues deterministically; LLM (OpenAI, `OPENAI_API_KEY`) authors a proposal per issue. Keeper proposals → `products/<product>/proposals/`. Project-scoped proposals → the project's own `proposals/` folder. **The tool NEVER modifies code.** Loop: change → review → triage → apply manually → commit. (Old auto-fix `--heal` retired — text rewrites corrupt code, string-match checks rot.) → `KB § 06-AGENTS.md`
- **Hound = code-hygiene orchestrator (the keeper-analog).** Where the keeper is **regulatory** (compliance contracts, LGPD checks, seed-compliance), the **hound** is **curatorial** (cleanup candidates across three orthogonal scopes). Single MCP entry point: **`noctus.hound.scan`** runs the absorption + fusion + optimization trio together, aggregates findings under `unified`, and emits a plain-text `next_action` recommendation (priority ladder: absorption-P0 → optimization-high → absorption-P1 → fusion-subsume → optimization-warning → ad-hoc). Use at end-of-phase polish + before architecture-cleanup decisions. The structural-duplicate filter in `scan_repetition` (default-on) skips empty `__init__.py` markers + already-absorbed re-export shims — without it the absorption queue is dominated by false positives. Don't trust inflated savings estimates (calibrated `min(a,b) × 0.15` after a 12× overestimate). Lives at `mcp/noctusai/tools/noctus/hound/`. → `KB § PATTERNS/architect/seed-absorption.md § noctus.hound.scan`
- **MCP-first — agent-exposable capabilities default to MCP.** When you want to expose a capability to agents (Claude Code, future bots, future product agents), the default surface is the MCP server at `mcp/noctusai/`. Dev tooling, business-logic primitives, vendor adapters all converge there as one growing wide-purpose toolkit. Naming: 3-segment dotted (`<umbrella>.<service>.<action>`). Pattern: Pydantic in/out schemas, hierarchical registration, lazy `NoctusContext` for business-logic tools. Composition belongs to the consumer. Boundary: if a capability has only one co-located consumer, a plain function is fine; MCP-first fires when a plausible second consumer exists. → `KB § 01-PHILOSOPHY.md § MCP-first`
  - **`scripts/` specialization:** a new automation script IS an agent-exposable capability → default = `noctus.dev.*` MCP tool + `cli.py` flag + colocated `Test*`, NOT a bare `scripts/*.sh|*.py`. Shell only for three named structural carve-outs (git-hook entry → thin dispatcher · pre-venv bootstrap · thin docker-orchestration), each needing a manifest row + accept-with-rationale entry. Keeper: `check_new_script_lacks_mcp_analog`. → `KB § PATTERNS/architect/mcp-first-scripts.md`
- **Clean folder — every artifact has a home.** Repo root holds only platform-wide files (CLAUDE.md, README.md, docker-compose.yml, .gitignore, scripts pointer, plus the `CLAUDE/` topical-rules directory). Audits / proposal drafts / design notes / scratch `.md` files belong inside a project folder as first-class reference artifacts quoted by `PROJECT.md §1/§5`. Stray root file → scaffold the project, move the file in, inline load-bearing bits into PROJECT.md, delete root copy. Prefer ONE umbrella project over N scattered one-finding folders. → `KB § PATTERNS/architect/project-execution.md § 11 Clean-folder principle`
- **LGPD-first, always.** Whenever code touches personal data (identity, financial, clinical, behavioral, derived embeddings, …), the LGPD lens is the **first** lens — before functionality, performance, UX. Clinical text is Art. 11 sensitive data; never leaves Therapy schema without a documented basis, never hits a response cache. When in doubt: `noctus.dev.lgpd_flag(...)` — records to `LGPD-WARNINGS.md`, notifies the user, **does not block**. The flag is a checklist item, ticked when resolved. → `KB § PATTERNS/security/lgpd.md`
- **Scaffolding a product auto-registers it to the noc dashboard.** `noctus.dev.scaffold_product` MUST also emit `products/core/backend/migrations/NNN_seed_<slug>_product.sql` (idempotent `INSERT … ON CONFLICT (slug) DO NOTHING` into `public.products`); the operator applies via Supabase MCP `apply_migration`. The dashboard reads `public.products` dynamically — a scaffolded product without a row is invisible. Slip surfaced 2026-05-05 by `media-scheduling` (on disk, missing from dashboard; that product was later consolidated into `social-wiring` and retired 2026-05-16 — the slip remains a valid dated illustration). Skip-with-surface only when `products/core/backend/migrations/` is absent (e.g., template workspace — "templates can't modify noc"). → `KB § GUIDES/new-product.md § Auto-registration to the noc dashboard`
- **Workspace ops + day-one-routes inheritance — scaffold ships a runnable product, not a skeleton.** `noctus.dev.create_testing_ground` (bootstrap) + `noctus.dev.scaffold_product` together drop **runnable** docker artifacts (`Dockerfile`, `Dockerfile.frontend`, `docker-compose.yml`, `.dockerignore`, `.env.example`), **runnable** ops scripts (`./start.sh` full|minimal|tunnel + health-poll + URL/cred summary; `./stop.sh` graceful|--volumes|--prune), AND a **runnable** day-one route skeleton (`example_router` + `schemas/example` + `services/example` + `Example.tsx` + 5 status-pinned tests). All inherited surface — source of truth lives at `templates/seed-workspace-docker/` (ops + docker) and `products/seed/` → `templates/product-seed/` (router skeleton, auto-synced by `noctus.dev.sync_seed_template`). **Never hand-author the inherited copy** — fix the template, re-run bootstrap. Trigger phrases for "online" → `./start.sh`; for "offline / shutdown" → `./stop.sh`. → `KB § GUIDES/deploy-workspace-online.md` + `KB § GUIDES/new-product.md § items 9-11`
