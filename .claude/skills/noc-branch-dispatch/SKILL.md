# noc-branch-dispatch — parallel engineer orchestration

The orchestrator IS the architect/tech-lead (plans + dispatches + integrates + stays with the user). Subagents ARE engineers (focused briefs, isolated worktrees, build + report, never plan orchestration). "branch yourself and dispatch" = the tech-lead self-branches its OWN inline slice AND dispatches engineers who EACH self-branch (apply this with `noc-self-branch`).

## Workflow (10-step runbook)

1. `noctus.dev.dispatch_preflight project_slug=<slug>` — fork-base + collision + env-pin + project-doc-phantom checks.
1b. **Read the global live map STATUS-FIRST, BEFORE you decompose** — `noctus.dev.branch_pointer action=list` (default `from_dev=True`). Scan **pointer statuses first**: `on_going` rows = live work → their `paths` are LIVE collision zones to plan around (even unshipped/un-integrated work); `blocked`/`stale`/`deferred`/`shipped`-but-undelivered rows = **leftover ground**. Use `branch_pointer action=query paths_overlap=[…]` to test a candidate slice against the whole tree. **Leftover-claim (whoever spots it, owns it):** to absorb a leftover, IMMEDIATELY flip its pointer to `on_going` with the new owner (+ a `notes` claim line) and push — so no second agent double-claims. Depth: `KB § PATTERNS/architect/branch-tree-tracking.md`.
2. **Decompose into file-disjoint slices** — classify collision-class per slice vs the GLOBAL map (not just local `git diff --name-only`): C1 disjoint → parallel-clean · C2 same-file-additive → brief additive-only · C3 substantive-overlap → re-scope to a sibling file OR sequence. Each engineer publishes its own pointer right before self-branching (`product-engineer` §1); you flip merged slices to `shipped` at integration.
3. One isolated worktree per engineer off `origin/dev` (`task_branch start` per slice).
4. **Dispatch in ONE message** (multiple `Agent` calls) so they run concurrently. Each brief ≤~15 lines, references `product-engineer`. Sonnet default; `model: opus` for judgment-heavy slices: semantics in one word of the brief, an open design choice, or expected fix-on-contact (`KB § PATTERNS/architect/dispatch-engineer-tuning.md` §4·1). Score every slice (`dispatch_log_completion score=`) — integrate refuses an unscored one.
5. Collect each engineer's short-form return + a `/tmp` patch overlay-safety copy.
5b. **On EVERY hand-back: salvage, then `TaskStop` that agent now** (not at session end): the harness holds a finished agent and its shells until stopped. Salvage = work + learnings (`learn-before-archive.md` "Stopping an agent or session is a teardown too"); take over its leftovers yourself (unfinished verdict, pending push, queued run - never park them in an idle agent). Your OWN dispatched agents only: never stop a peer session unless the owner says so. The `background-agent-idle` hook names stragglers. → `KB § PATTERNS/common/background-agent-lifecycle.md`
6. **Detect collisions** — (a) path-overlap AND (b) semantic-duplicate git can't see.
7. **Enqueue each ready slice as soon as it is green — via the elected steward** (2026-11-05, supersedes "merge all before integrating"): ONE leader session per machine holds the CI/deploy role (`release_steward`); check `ListAgents` + `release_steward action=status` first. You ARE the steward (or claim it when none is elected, then announce to peers via `SendMessage`) ⇒ drain `release_steward action=inbox` and run `task_branch action=enqueue slug=<slug> confirm=true` per slice in one batched pass, `ack` each, and reply `LANDED <dev sha>` / `EJECTED <reason>` to each requester. You are NOT the steward ⇒ file each ready slice with `release_steward action=request slug=<slug>` and KEEP DISPATCHING/BUILDING the rest — gated is not blocked, never wait. Dispatched engineers never enqueue or ship; their leader does (a steward's subagents act under its lease). → `KB § PATTERNS/devops/release-steward.md` The CI merge queue batches whatever is waiting, tests the COMBINED tree on GitHub runners, bisects a red batch and ejects only the culprit — batching is the queue's job now, not a local train. A slice that is ejected goes back to its engineer with the reason. `task_branch action=train` still exists for slices that genuinely need a joint conflict resolution (the queue merges a train `--no-ff`, so its resolutions survive). → `KB § PATTERNS/devops/merge-queue.md`
8. Engineers run only the narrowest scoped check; the tech-lead runs `noctus.dev.gate_sweep` on any slice touching `mcp/`, migrations, KB or compliance surfaces BEFORE enqueueing (an ejection costs a ~25-min CI cycle). The full merged-tree gate is the queue's CI run — never a local merged-tip run on this machine.
9. Cleanup worktrees: `task_branch action=landed slug=<slug> confirm=true` once the queue reports landed (pointer, primary FF, worktree + branch teardown); the SessionStart sweep reclaims abandoned merged+clean ones. Keep about 3–4 writing sessions/engineers live at once.
10. Gate `main` only at 100% — human-gated per R4.

## Guardrails
- Below `<100 LoC ∧ <3 files ∧ single-phase` → the architect does it **inline** (don't pay the ~45–60k engineer contextualization tax). 2+ small file-disjoint tasks ride ONE compound brief.
- Wave N+1 dispatches only after every Wave N slice **FF-merges** (not just reports).
- **One isolation primitive per engineer:** `task_branch` briefs run WITHOUT `Agent(isolation='worktree')` — both pins the git sandbox to the agent worktree (can write, never commit). → `KB § PATTERNS/architect/branching-dispatch.md` § Isolation.
- **Change propagation.** You change methodology (CLAUDE.md, `CLAUDE/*`, PATTERNS, `.claude/{agents,skills,commands}`, hooks, settings) or shared plumbing mid-flight ⇒ `SendMessage` HEADS-UP to your own live dispatched agents, and (for a landing) to every live peer in `ListAgents`; inform only, never steer a peer; a notice is information, the receiver decides how to proceed and never waits on the owner for it; on a conflict or error the receiver replies and the two resolve it together (silence is not OK). → `KB § PATTERNS/architect/orchestration-craft-canon.md` §6.13
- Engineers commit ONLY their own branch; tech-lead owns all merging/pushing/blessing.
