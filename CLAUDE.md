# CLAUDE.md · v3.0 — router

> **What this file is.** Auto-loaded every session. Two jobs: (a) the universal behavioral rules Claude obeys every turn, (b) routing pointers into `CLAUDE/<topic>.md` (topical rules, on-demand) and `KNOWLEDGE-BASE/` (depth, on-demand). Kept lean on purpose — the auto-loaded budget compounds across every reply.
>
> **What this file is NOT.** A tutorial, changelog, spec sheet, manual, or rule body container. Bodies and depth go elsewhere. If you find yourself writing >80 words on a single rule here, push the long-form into KB and shorten the rule to a pointer.
>
> **When you can't find a rule:** open `CLAUDE/<topic>.md` (sibling of this file) for topical rules, or `KNOWLEDGE-BASE/INDEX.md` for depth.

## 1 · Universal rules

Each bullet is rule + one-clause why + pointer. Bodies / examples / slip-history live in the pointer target. Soft cap ≤80 words/bullet (`KB § PATTERNS/project-execution.md § 2.8`).

- **Vocabulary — methodology, not doctrine.** Use *methodology / rule / principle / convention / pattern / working agreement.* Avoid "doctrine / doctrinal" — hierarchical framing runs counter to how this team operates. → `KB § 01-PHILOSOPHY.md § Vocabulary — methodology, not doctrine`
- **Seed first. Always.** Every product inherits via `create_product_app()` (backend) / `createProductApp()` (frontend). Customizations flow through NAMED seams (`standard_routers=[...]`, `authProvider`, `lifespan_*`, …). A customization NOT through a named seam = structural fork — refactor or accept-with-rationale. **Don't ask whether to use the seed; the seed IS the approach.** Run the 4-question Practical Decision Test before any structural change. → `KB § 03-SEED-ARCHITECTURE.md § Seed as Skeleton` + `§ Practical decision test`
- **Verify the seed ships it — before locking any "consume the seed X" decision.** Read the module's `__init__.py` exports + the concrete adapter file; confirm runtime path covered, not just the Protocol or Fake. Gap + N=1 consumer → ship against Fake, surface follow-up. Gap + N=2+ consumers → DRY-recurrence, file the seed real-adapter project. Slip looks like *"the seed has Protocol X, so we can do Y"* when only the Fake ships. → `KB § 03-SEED-ARCHITECTURE.md § Verify-the-seed-ships-it test`
- **Seed IO modules ship Fake+Real with factory.** Every seed module touching IO (HTTP, DB, vendor SDK) ships in **Protocol + Fake + Real + factory** shape mirroring `integrations/google_calendar` + `google_maps`. Pure-logic / crypto / shaping modules exempt — exemption test: *"would a Fake here exercise different code than the Real?"* If no, exempt. Half-shipped (Protocol+Real only OR Protocol+Fake only) generates consumer-side forks at the seed level — fix at the seed before consuming. → `KB § PATTERNS/seed-fake-real-adapter.md`
- **No incomplete commits.** Backend and frontend at the same maturity. "Scaffolded" is not "complete." If one side is real and the other is a placeholder, stop and flag.
- **No quick fixes.** A fix that touches multiple products for the same reason is at the wrong level — go up to seed / shared lib / config and let it propagate. Thirty minutes on the root beats five minutes on a patch that generates future work.
- **No workarounds — and no monkey-patching, in production OR tests.** Use the real API/SDK/framework. **The rule applies to test code too.** Never `monkeypatch.setattr(our_module, "our_guard", _noop)` — that test no longer exercises the guard. Right shape: seed real underlying data; use dependency injection for write side-effects; read inserts via `MockRequestBuilder.inserted_payloads`. `unittest.mock.patch.object(<external_integration>, ...)` for **external services** (LLM APIs, transcription, network) is fine. → `KB § 01-PHILOSOPHY.md § No workarounds` + `KB § PATTERNS/testing.md`
- **Estimate off evidence, not structure.** Before offering A/B/C, a session-size, or "this is quick" — open the files the change would actually touch. If it touches `seed/`, a shared lib, a factory, or any cross-cutting layer, read that code first. → `KB § 01-PHILOSOPHY.md § Estimate off evidence`
- **Codebase is source of truth; docs/summaries/memory are derived.** Docs / summaries / memory / another agent's report / PROJECT.md §11 are *derived* and drift. Before acting on any such claim — resuming, picking up another agent's work, acting on a recalled memory — **the first command verifies it against the tree** (`git status`/`git diff`/`Read`/`pytest`/ledger); state "grounding in actual tree state." Doc disagrees with code → code wins, fix the doc same change. → `KB § 01-PHILOSOPHY.md § Codebase is source of truth`
- **Fix-on-contact for pre-existing debt — fix THEN surface, never surface-only.** Bumping into a pre-existing failure/bug/drift while doing other work does NOT license leaving it. Always all three: (1) verify pre-existing vs baseline; (2) **fix it in-flight**; (3) surface problem + root-cause + *solution applied*. Surface-only = silent-error shape one level up. Exceptions (never silent): out-of-safe-scope (hard-to-reverse/security/needs-a-decision) → surface with recommendation + named destination + reason; or balloons into a project → file it. Default = fix on contact. → `KB § 01-PHILOSOPHY.md § Fix-on-contact for pre-existing debt`
- **DRY — the recurrence rule.** **N=2 → triage time** (formalize / refactor / accept-with-rationale; decision recorded; silently moving on forbidden). **N=3+ → MUST formalize** (extract into seed-lib / framework / shared library; minimum response = file a follow-up project; silently shipping the 4th instance forbidden). When the rule fires: STOP, name the pattern, decide the destination, file or apply, resume. → `KB § PATTERNS/project-execution.md § 2.7 The recurrence rule`
- **Componentize everything.** Check `KB § 04-SHARED-LIBRARY.md` before writing anything new. If another product will need it, build it shared from day one. → `KB § 04-SHARED-LIBRARY.md`
- **Reading & research discipline — narrow-read; delegate breadth.** **Narrow-read first**: structure before bodies for any file >200 lines or unknown range — outline via grep/small-`limit` `Read`, fetch bodies only for what you'll edit/cite/reason about; whole-file reads reserved for short files / full reviews / content-is-structure. **Explore-agent delegation**: delegate to the Explore subagent when answering needs **3+ targeted greps, multi-file walking, or open-ended discovery** (trigger = research breadth, not product count); direct `Read`/`grep` when the path/symbol is known; prefer dedicated `noctusai_*` scan tools. → `KB § PATTERNS/agent-reading-discipline.md § Narrow-read first` + `KB § PATTERNS/agent-reading-discipline.md § Explore-agent delegation`
- **Replication-to-seed symmetry — fires at READ/PLAN/DESCRIBE time.** *The trigger is LANGUAGE.* Phrasings like **"per-product X"**, **"mount across N products"**, **"for each product Y"** ARE the slip — wherever they appear (your reply, project docs, user prompt). The right per-product code count for a cross-product concern is **zero**. Authoring-time corrective: every `PROJECT.md` MUST include §3a Seed-first analysis BEFORE §6. → `KB § PATTERNS/project-execution.md § The replication-to-seed symmetry rule` + `KB § GUIDES/seed-first-design.md`
- **AST-first — never regex code edits.** Code changes go through an AST tool: `libcst` (Python), `ts-morph` (TypeScript), `tree-sitter` (cross-language). Regex/sed/awk only for prose, search, log inspection. Boundary: *if a compiler/interpreter/type-checker parses the file, use the AST tool.* **Structural-refactor corollary**: grep misses segmented construction — pytest + builds are the oracle. **Always-outline-able invariant**: pre-commit `check_files_outlined` blocks any staged un-AST-readable file (`cli.py --check-outlined`); `noctus.dev.scan_outlined` audits (baseline zero). → `KB § 01-PHILOSOPHY.md § AST-first` + `KB § PATTERNS/ast.md` (§ Always-outline-able platform)
- **Flag MCP-first / AST-first opportunities proactively.** Bystander rule: working elsewhere and you spot a missed exposure (a capability that should be MCP, or a sed/regex edit that should be AST) — **apply now** if cheap, or **defer with destination** (active project `**Improvements:**` / accept-with-rationale / follow-up project). Silent skipping forbidden — same shape as silent errors. → `KB § 01-PHILOSOPHY.md § Flag MCP-first / AST-first opportunities proactively`
- **Hygiene scanning — run the keeper-analog tools before walking away.** **Absorption-search (standing duty)**: editing a product's services/routers/hooks — *even unrelated work* — run the MCP scan sextet (`scan_cross_product_helpers` + `scan_within_product_helpers` + `scan_service_line_recurrence` + `scan_block_patterns`) before/after; within-product N=2 needs architect-eyes in Phase 0 (scanners threshold N≥3). **Code hygiene**: `noctus.hound.scan` = single entry for absorption (file-level) · fusion (cross-tool) · optimization (intra-file), emits `next_action` (default *"what cleanup is urgent?"*); keeper = regulatory, hound = curatorial. **Storage hygiene**: `noctus.dev.mole` / `bash scripts/mole.sh scan` over artifacts · environments (advisory) · stale `.claude/worktrees/agent-*/` (`sweep --force` destructive, dry-run default; never deletes uncommitted/main/siblings/`.env`/migrations); triggers pre-dispatch + pre-commit + bootstrap. → `KB § 06-AGENTS.md § Absorption-search sextet` + `KB § 06-AGENTS.md § Code-hygiene trio` + `KB § PATTERNS/seed-absorption.md § noctus.hound.scan` + `KB § PATTERNS/storage-hygiene.md`
- **Triage at decision time — formalize / refactor / accept-with-rationale.** Every divergence from ideals lands on one of three explicit outcomes: **formalize** (extend framework/seed), **refactor** (align with contract), or **accept-with-rationale** (catalog the entry in `KB § PATTERNS/accept-with-rationale.md` — durable register that survives project folder deletion). "Accept" is a real landing — paperwork keeps it from going silent. Recurrence flips prior `accept` outcomes toward `formalize`. → `KB § 01-PHILOSOPHY.md § Triage at decision time` + `KB § PATTERNS/accept-with-rationale.md`
- **Safety nets capture failures; failures become learnings; methodology evolves.** Methodology is incomplete by design. Safety nets — `git merge` (merging gap), drive-by-exception (hook false-positives), `git stash` (switch blockers) — keep the system working at a gap. **Capture the learning** + **update the methodology** (three-way sync) so the gap closes structurally. The safety net firing IS the methodology working. Anti-patterns: bypassing the net to hide the gap (`--force` instead of merging); learning lives only in §11 prose; same catch never formalized. → `KB § 01-PHILOSOPHY.md § Safety nets capture failures; failures become learnings; methodology evolves` + `KB § PATTERNS/project-execution.md § 2.11 Phase enrichment loop`
- **Branching-first orchestration — parallelize by default; orchestration STAYS with the orchestrator.** **The orchestrator IS the architect** (plans + dispatches + evaluates + stays available to the user); **subagents ARE engineers** (focused briefs, narrow context, isolated worktrees, build + report). Default mental model: "can this chunk into parallel branches?" — if yes, `git worktree add` per engineer + dispatch in a single `Task` turn + maintain findings.md; if no, serial (justified, logged) or master-tree-parallel-batches for N≥2 same-shape. **Engineers execute, never plan orchestration.** **Engineer findings evaluated locally + applicable fixes applied SAME SESSION** (three-way sync); deferring an applicable fix = silent-error shape. → `KB § 01-PHILOSOPHY.md § Branching-first orchestration` + `§ Roles: Architect + Engineers` + `§ Knowledge tracking — durable findings file` + `KB § PATTERNS/branching-and-merging.md § 16`
- **Knowledge tracking — durable findings file for any non-trivial work.** Any non-trivial project/feature/orchestration keeps a root `findings.md` (5 categories: slips/errors/mistakes/lessons/knowledge). Append in-the-moment; synthesize at close. Default-on for projects + master-trees + parallel-orchestration; trivial fixes may skip but **log the absence** to `phase_learnings` SQLite (silent skip forbidden). Distinct from `phase_learnings.db` + §11 (findings.md = what-we-LEARNED, curated). **Architect briefs MUST carry an explicit findings.md/PROJECT.md/proposal Write-authorization** — engineers inherit a no-`.md` default and refuse without it. → `KB § 01-PHILOSOPHY.md § Knowledge tracking` + `KB § PATTERNS/branching-and-merging.md § 17.6`
- **Wave-based dispatch + pause-on-dependency + scoped-team economics.** Group chunks by dependency-depth: Wave N+1 dispatches only after every Wave N chunk **FF-merges** (not just reports). Engineer surfaces a mid-flight gap → **pause** chunk, **dispatch a focused dependency team**, **resume** on merge (engineers never absorb dependencies). **Split rather than combine** — a 200-LoC focused brief beats a 2000-LoC one; token cost acceptable, quality is the constraint. → `KB § PATTERNS/branching-and-merging.md § 18`
- **Pilot-products-first refactor cadence.** A seed/shared-lib/framework change does NOT refactor all ~10 products in one wave. Prove it on 3 canonical pilots — **`erp-imobiliario` · `therapy-platform` · `social-wiring`** (+ `core` if control-plane) — then non-pilots extend in a **later wave gated on pilots-green**. Deferring a non-pilot here is the rule, not a silent error (destination = the extend wave); don't leave partial non-pilot adaptations. Recurrence/formalize-to-seed still fires; this only scopes validation fan-out. → `KB § PATTERNS/project-execution.md § 2.12`
- **No silent errors — always explicit fix opportunities.** No `except: pass`, no silent degraded fallbacks, no deferred items without a named destination, no "verification ✓" when the tail showed red. Ambiguity is a silent error — ask. Absence of findings is a claim — quote the command that confirms it. → `KB § 01-PHILOSOPHY.md § No silent errors`
- **Doc-propagation sync — KB ↔ CLAUDE.md ↔ memory ↔ tool-code move together.** Any rule/methodology/behavior change lives in **all three doc layers same session** — ordering: KB-first → CLAUDE.md (or topical) pointer → memory entry + MEMORY.md line; amending an existing rule touches all three. Extends to **tool-code ↔ doc-prose**: when a tool (script/MCP/keeper/CLI) changes behavior (flag/mode/rename/severity) every referencing doc updates in the **same commit** (KB patterns, Situation→Tool maps, CLAUDE.md pointers, INDEX.md, `--help`, product README/MASTER-PROMPT) — "later" forbidden; discovery `grep -rn "<tool-name>" KNOWLEDGE-BASE/ CLAUDE.md CLAUDE/ products/*/README.md`. `verify-kb-sync.sh` catches dangling KB↔CLAUDE.md pointers, not missing memory entries (agent discipline). → `KB § 01-PHILOSOPHY.md § Docs stay in sync` + `KB § PATTERNS/methodology-codification-pipeline.md § 8 (Situation → tool map)`
- **Durable docs are self-contained — never anchor knowledge to `projects/`/`archive/`.** KB/`CLAUDE.md`/memory outlive projects; `archive/` is not persisted long-term, so pointing a durable doc at `archive/projects/<…>` becomes a dangling pointer to lost knowledge. **Inline the durable substance**; reference code/files + dated facts, never project slugs or archive paths. Sanctioned durable indices: `project-history/ledger.ndjson` + the accept-with-rationale catalog. → `KB § 01-PHILOSOPHY.md § Durable docs are self-contained`
- **Symbol-first when authoring dense docs.** When authoring/refactoring dense docs **or AI-intended files** (MASTER-PROMPTs, CLAUDE.md, KB patterns, memory bodies; **AI scaffolding** — whole PROJECT.md + `proposals/*.md`, `findings.md`, the dispatcher coord-file, `live-patterns-log.md`, dispatch briefs + `.claude/agents/*.md`; §1 framing / §2 quoted-user stay prose; from-now-on, existing not retrofitted) use the doc-symbology glossary by default: `∧ ∨ ¬ ⇒ ↔` (logic) · `✅ ⏳ ❌ 🔒 📋 🗑 ⭐` (status) · `s1/s2/s3/s4` · `[F]/[R]/[A]` · `N≥3 Δ Σ`. One fixed meaning/symbol; lossless-swap test gates each swap. NOT for: error messages, first-paragraph, quoted user, bug-fix comments, commits. `→`=routes; `⇒`=implies (never interchange). **This is the standing pattern every future doc edit follows** — caveman-validated; `check_doc_symbology_drift` scans all symbol-eligible docs against the live glossary (platform baseline: zero-drift). → `KB § PATTERNS/doc-symbology.md`
- **Finish the session — verify, don't assume.** End-of-session checklist: `cd products/<touched>/frontend && npx vite build`; `cd products/<touched>/backend && pytest`; `cd mcp/noctusai && pytest tests/` if MCP-toolkit changed; report any regression. Don't mark "done" while a build or test is red. *Every in-session change must land on green.*
- **Never auto-commit or push, except project gates; commit + push only your own work.** Two carve-outs: (a) end-of-phase local commit (no push); (b) final commit + `git push` at project close (literal last step, after folder deletion). `git status` first; never `git add .` / `-A`. Stage only files YOU authored this session — explicit-path `git add` does NOT validate authorship. Verify via `git diff --cached --name-only` before commit, `git log origin/<branch>..HEAD` before push; surprise entries → unstage / ask. **Terminal commit-guarantee:** a session never ends with own-authored work uncommitted/unhanded-off in the shared primary tree (residue forces next-agent reconciliation) — `git status` sweep before "done"; every own entry committed ∨ handed-off-with-destination ∨ restored-with-rationale. → `CLAUDE/projects.md § Commit per phase, push at project close` + `KB § PATTERNS/project-execution.md § 2.10` + `.claude/agents/engineer-default.md § 2a`
- **Context budget discipline.** `CLAUDE.md` (this file) = router. `CLAUDE/<topic>.md` = topical rules, read on-demand by agent discipline (see §3). `KNOWLEDGE-BASE/` = depth. **MCP keep-list**: `noctusai` + `supabase` only — anything else needs explicit user approval. **Skills keep-list**: `update-config` / `loop` / `schedule` / `security-review` only. New rule → KB-first → CLAUDE.md (or topical) pointer → memory. New §1 bullet >80 words → trim and push depth to KB. → `KB § 01-PHILOSOPHY.md § Context budget discipline`
- **Lossless doc-refactor — changing the doc-set itself is methodology surgery.** Any compact / restructure / merge-rules / fold-in-external on CLAUDE.md / KB / MEMORY.md / `.claude/agents` / MASTER-PROMPTs follows the framework: lossless **proven not asserted** via diff gates (pointer-set ∧ rule/section ∧ line-structure ∧ index-pointer ∧ hook-grade); gated-aggressiveness ladder (s-lossless no-approval / s-moderate show-diff-first / s-plan-only); trim only what the pointer target provably carries (registers ≠ prose); symbol-first scan-enforced (zero-drift); file-disjoint-or-inline parallelization w/ architect true-disk 100%-certification; fix-on-contact; three-way-sync close. The trigger is the task class, not the file. → `KB § PATTERNS/lossless-doc-refactor.md`
- **Sibling workspaces consume noc read-only, whole — never modify, never trim.** A template/seed workspace is a noc sibling consuming 8 noc surfaces via read-only symlinks. **Cannot modify noc** — three-layer defense: (1) PRIMARY template pre-commit refuses commits touching symlinked paths or non-sandbox additions without a `.promotions/<slug>.md`; (2) AGENT this rule + KB + memory; (3) SYMBOLIC chmod -h a-w. Edits to symlinked surfaces belong in noc; additions go through the promotion manifest + `noctusai_promote_from_template`; `PROMOTIONS.md` is **derived** (never hand-maintain). **Inherit whole, trim none** — auto-load is already minimal (`CLAUDE.md` router; KB on-demand; `MEMORY.md` index); trimming breaks seed-first analysis, recurrence scans, KB pointer integrity (`verify-kb-sync.sh`), three-way sync. Per-product focus → `products/<slug>/MASTER-PROMPT.md`; the workspace IS `noc + product`, not `subset(noc) + product`. → `KB § PATTERNS/template-workspace.md` + `KB § PATTERNS/seed-workspace.md § Promotion manifest` + `KB § PATTERNS/seed-workspace.md § Why the inherited surface is not trimmed`
- **Divergent-architecture absorptions refactor to the house container model.** An incoming externally-developed product whose container architecture differs from noc's single-container house model MUST be refactored to the house shape on absorption — one container, uvicorn serving API+SPA via `serve_spa`, `FROM noctus-seed-*-base` seam, two compose projects on external `noctus-net`. No fleet carve-out. Newly-scaffolded products inherit by construction (fires only for *absorptions*). Fold only still-relevant divergent infra. → `KB § PATTERNS/containerization.md § 12a` + `KB § GUIDES/absorb-seed-workspace.md`
- **Parallel-agent collision protocol — STOP, wait, continue.** When a shared-file edit is reverted by another agent's work AND re-applying would loop, do not loop-fight: STOP after the second revert. **Do NOT file a collision-report project** — wait for the parallel agent to finish. Continue with non-colliding deliverables; catalog the deferred work in `accept-with-rationale.md`. Surface in the end-of-work summary; re-apply when the user signals or the parallel project closes. N=2 collisions on different files same session → pause + surface to user. → `KB § PATTERNS/project-execution.md § 2.9`

## 4 · Sync rule

CLAUDE.md, `CLAUDE/<topic>.md` files, and `KNOWLEDGE-BASE/INDEX.md` stay in sync — when you add, rename, or delete any KB file or folder, every layer that references it gets updated.

**Pre-commit hook enforces it** (`scripts/pre-commit` → installed by `scripts/install-hooks.sh`). On every commit:
1. Syncs `products/seed/` → `templates/product-seed/` if staged.
2. Runs `scripts/update-kb-counts.py` — regenerates auto-derived count blocks.
3. Runs `scripts/verify-kb-sync.sh` — **blocks the commit** if any literal `KNOWLEDGE-BASE/…md` pointer in CLAUDE.md or `CLAUDE/*.md` doesn't resolve, or any KB doc is missing from `INDEX.md`.

Manual runs:
- `bash scripts/verify-kb-sync.sh`
- `python scripts/update-kb-counts.py [--check]`
- `python mcp/noctusai/cli.py --verify-kb-sync`

Install hooks in a fresh clone: `bash scripts/install-hooks.sh` (full setup: `bash scripts/setup.sh`).

Bypass (rarely correct): `git commit --no-verify`.
