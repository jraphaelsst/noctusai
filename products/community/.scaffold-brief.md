# Scaffold brief

Captured at scaffold time. The LLM-rewritten prose surfaces (README.md, MASTER-PROMPT.md) reference these answers — edits here should be propagated to those files manually or via a re-rewrite pass.

## What real-world domain does this product serve? (e.g. 'B2B real estate analytics', 'social media post scheduling', 'mental health therapy sessions')

Online community management center for a single paid online community for women, run by client Mônica Tangerino (theme not yet defined). pt-BR only, responsive web.

## Who is the primary user? (e.g. 'real estate brokers', 'small business marketing teams', 'licensed therapists')

Community managers in a back office (roles: admin = everything; moderator = moderation + content) and community members in their own member portal.

## What are the 3-5 core entities/concepts? (e.g. for ERP: 'Imovel, Cliente, Negocio, Equipe')

Membro (profile, tags, segments, lifecycle), Plano (manager-configurable paid tiers + entitlements), Assinatura/Pagamento (Stripe card or Asaas Pix/boleto, member chooses), GrupoWhatsApp, Post/Topico (feed + forum), Conversa (chat), Conteudo (library: embeds, Supabase-stored MP4 uploads, live-room recordings), Evento (external link / built-in live room / in-person with check-in), Pontuacao (engagement points), Moderacao (AI-flagged items queue).

## Describe 1-3 primary workflows the product enables, end-to-end.

1) Entry: public tier checkout OR application + manager approval OR invite-only -> account + tier entitlements. 2) WhatsApp groups: tier<->group mapping; system prepares add/remove batches a manager confirms (semi-automatic, WAHA ban-risk mitigation); broadcasts; message ingest feeds engagement and moderation. 3) Native space: feed, forum, real-time chat, tier-gated content library and events with RSVP/check-in; points from platform, WhatsApp and events/content; AI flags content from platform + WhatsApp, a human manager approves each action.

## External services this product integrates with (LLMs, APIs, webhooks, etc.). 'none' is fine.

Stripe (card) + Asaas (Pix/boleto) payments; WAHA WhatsApp incl. group operations; LiveKit live rooms (multi-party, recording); Supabase Storage for video (MP4 + signed URL now, HLS later); LLM moderation via noctusai_lib.integrations.llm; Google Calendar/external meeting links.

## How will we know the product is doing its job? (key metrics, user outcomes)

Growing active paying members and MRR; low churn / long membership duration; engagement (weekly active members, posts, event attendance); less manual manager work for WhatsApp, access and moderation.

## Naming conventions specific to this product's domain? (e.g. 'use Portuguese for entities, English for code')

Portuguese for DB tables, entities and routes (membros, planos, eventos); English for code structure; UI copy pt-BR. Display name 'Community', slug/schema 'community'.
