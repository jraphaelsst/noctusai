# Expo project setup — what actually happened, and the fixes

## Before creating anything: check the machine
```bash
node -v; npm -v                          # Homebrew node/npm on macOS is fine
ls ~/node_modules ~/package.json 2>/dev/null   # MUST be empty — see "stray home npm" below
xcode-select -p                          # /Applications/Xcode.app/... for iOS builds; CLT-only is enough for Expo Go
gh auth status                           # if you'll create the GitHub repo from the CLI
```

### Stray `~/node_modules` breaks Expo tooling (verified 2026-10-03)
A `package.json` + `node_modules` in the **home folder** (an old accidental `npm install` there)
shadows the real npm: Expo's CLI resolves `npm` by walking up parent folders and found
`~/node_modules/npm` **5.1.0 (2017)**. Symptoms:
- `create-expo-app` → `Could not parse JSON returned from "npm pack ... --dry-run"`
- `npx expo install` → `npm ERR! cb.apply is not a function` (log says `using npm@5.1.0`)
Worse, it silently fed **old major versions** (vite 5, react-router 6, eslint 8) to any project with a
missing/partial local install. Fix: move it aside (`mv ~/node_modules ~/package.json ... ~/.backup/`),
reinstall affected projects from their lockfiles (`npm ci`). Verify with a resolver scan: for each
project's declared deps, `require.resolve(dep, {paths:[projectDir]})` must not land in `~/node_modules`.

## Creating the project
`npx create-expo-app@latest <name> --template default` (TypeScript + Expo Router).
If the generator itself fails, the template is a plain npm tarball:
```bash
npm pack expo-template-default@latest           # in a scratch dir
mkdir app && tar -xzf expo-template-default-*.tgz -C app --strip-components=1
mv app/gitignore app/.gitignore; mv app/_vscode app/.vscode
# set package.json name/version/private, app.json name/slug/scheme; npm install
```

## Things the template doesn't tell you
- `expo-env.d.ts` (`/// <reference types="expo/types" />`) is generated by `expo start`; `tsc` fails on
  CSS-module / `global.css` imports until it exists. It's gitignored — create it locally for CI type-checks.
- `npx expo export --platform web` is a fast full-bundle sanity check (also lists every static route).
- Remove the template's example screens/components/assets early; keep `assets/images/icon.png` etc.
  that `app.json` references until you replace them.
- Always add deps with `npx expo install <pkg>` (picks the SDK-compatible version), then
  `npx expo install --check`.

## Project layout that worked
```
src/app/            routes ONLY (Expo Router); route files export only the screen component
src/components/ui/  primitives (AppText, Button, IconButton, Chip, Screen, ListRow…) + icons.ts
src/components/     domain components (cards)
src/theme/          tokens.ts · typography.ts · fonts.ts · index.ts  — single source of visual values
src/data/           typed static content
src/lib/            pure logic (testable, no React)
src/state/          providers + persistence
docs/               spec, design decisions, mockups
agents/             consumed agent packages
```
Path alias `@/*` → `src/*` is preconfigured in the template's tsconfig.
