## What real-world domain does this product serve? (e.g. 'B2B real estate analytics', 'social media post scheduling', 'mental health therapy sessions')

Environmental-education for companies (recycling, reuse, waste reduction) by One Consultoria. The product is the home of Julia — an AI assistant (Claude Agent SDK, headless) who holds the project's history, decisions and knowledge base and helps invent and build a future video-first training platform. Absorbed from the sibling workspace built for noc (P0-P2 shipped: brain, MCP server, backend runner + approval gate).

## Who is the primary user? (e.g. 'real estate brokers', 'small business marketing teams', 'licensed therapists')

Today: Rapha / the One Consultoria team, who manage Julia, her persona and her conversations from the app UI (and later WhatsApp). Later: learners and client-company contacts of the training platform.

## What are the 3-5 core entities/concepts? (e.g. for ERP: 'Imovel, Cliente, Negocio, Equipe')

AgentPersona (name, role, tone, system-prompt append, model, effort) · Conversation (one thread shared by web and WhatsApp, one Agent SDK session) · Message (role, channel web|whatsapp) · Approval (tool-call gate: pendente|aprovada|negada|expirada) · Brain index over git-backed files: KnowledgeEntry, Decision (D-nn), OpenQuestion (Q-nn), Task (T-nnn)

## Describe 1-3 primary workflows the product enables, end-to-end.

1) Chat with Julia in the web app: message -> agent turn streamed over SSE (tool cards live) -> any write asks first -> approve/deny inline -> approved KB/MCP write lands as a commit in the git-backed brain; timeout denies. 2) Manage Julia: edit persona/model/effort without deploy; browse the knowledge base; follow roadmap, tasks, decisions and open questions. 3) (Deferred, P4) the same thread over WhatsApp via WAHA plus an inbox with manual takeover.

Claude Agent SDK (claude-opus-5, headless) + Anthropic API; noctusai_lib.realtime SSE over Redis; git (brain persistence, one commit per approved write with provenance trailers); WAHA via noctusai_lib.integrations.whatsapp — deferred: prod WAHA is CORE tier (single session, owned by social-wiring). In prod Julia may only write through academia.* MCP tools — no Bash, no code writes.

## How will we know the product is doing its job? (key metrics, user outcomes)

Derived from the sibling roadmap's per-phase done-when (the source states no product-level metrics): talking to Julia in the browser with a streamed reply that is persisted; persona editable from the UI with no deploy; every approved write visible as a git commit and in the KB browser; all five sidebar slots (Chat, Config, KB, Roadmap/Tasks, Inbox) showing real data; later, a WhatsApp message answered in the same thread.
