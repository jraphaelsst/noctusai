# Core Platform

Central platform for authentication, organization management, billing, licensing, and SSO. Serves as the admin dashboard and gateway to all NoctusAI products.

## Stack

- **Backend**: FastAPI (port 8000)
- **Frontend**: React + TypeScript + Vite (port 5173)
- **Database**: Supabase (schema: `public`). `org_settings` (vendor credentials), `webhook_endpoints`, `webhook_deliveries` and `api_keys` are **service-role only** (migration 086): no anon/authenticated grant or policy; every access goes through the API's admin-gated routes. `ai_usage` (migration 091) is the central append-only LLM usage ledger of every product -- service-role insert, member/platform-admin read, read by `/api/admin/llm-usage`. `dev_telemetry_claude` / `_os` / `_jobs` / `_marks` (migration 097) are **dev telemetry**, not product data: how our own development work uses Claude (tokens, API-equivalent cost, chars per session/agent) and the dev machine (heavy jobs, OS samples), written by `noctus.dev.usage_eval` (service role, counts only), RLS on with no policies, read by the usage dashboard (`KNOWLEDGE-BASE/CONTEXT/PATTERNS/devops/usage-evaluation.md`)
- **Tenant key**: `org_id`
- **Auth**: Custom REST API

## Running

```bash
# Backend
uvicorn app.main:app --reload --port 8000 --app-dir products/core/backend

# Frontend
cd products/core/frontend && npm run dev
```

## Key Features

- Organization creation and management
- Org brand identity (`/api/brand`, page `/org-settings/identidade`): one visual identity per org — colors, fonts, radius, logos, favicon, derived dark mode — applied to core and every product by the seed `BrandProvider`; NOC standard when unset; `.md`/`.pdf` design-system upload analyzed by Claude into a validated, versioned draft; the DB refuses any stored identity without the `noctus.brand-tokens/v1` schema (migrations 089 + 094)
- Admin > Templates (`/api/admin/templates`, page `/admin/templates/*`, migration 092): DB-backed, versioned platform template library by kind (design system, agents/prompts, messages, documents, repo/workflow) and scope (platform or product); edit = new version, activate archives the previous; design-system templates seeded from the NOC standard tokens and validated with the brand-token rules; a read-only "Fontes" catalogue lists template-like assets that still live outside the DB. The filesystem scaffold browser moved to `/api/admin/template-scaffolds`
- Platform Notificações (`/api/admin/notifications`, page `/admin/notificacoes`, platform admins; owner 2026-11-09): every owner-facing notification the products declare (seed `notification_catalog` → `public.notification_kinds`, migration 117), grouped per product, with a per-kind and per-product on/off switch (products honour it within 60 s), 30-day counts per dispatch status and the send history (`public.notification_sends`: no message text, no phone numbers). The same page manages who receives the owner notices over the NoctusAI line: `GET/POST /recipients`, `PATCH/DELETE /recipients/{id}`, `GET /owner-line` (`public.notification_owner_recipients` — number immutable, removal via RPC `remover_destinatario_dono` — + append-only `…_events` written only by a SECURITY DEFINER trigger, service_role read-only, migration 118). The page lists EVERY live product (`ativo` + `deploy_scope='live'`, plus core) even when it declares no kind (`declared: false`), and `public.notification_owner_recipients` is the platform's ONE owner number (agents' hand-off number reads it; migration 121 copied the old agents value in). Core declares `skill_scout_novo_skill` (WhatsApp only) and sends it via `POST /api/admin/notifications/skill-scout`. KB `PATTERNS/backend/owner-notification-catalog.md`
- Platform Operação (`/api/admin/operations`, page `/admin/operacao`, platform admins): every product's scheduled jobs from the seed scheduler run ledger (`public.scheduler_runs` / `public.scheduler_jobs`, failures alert admins in-app at most once per job per 6h), container health (`/api/fleet`), the seed model catalog, LLM spend + cost ledger, and the owner daily brief (07:00 platform tz, code-only — no LLM; in-app + e-mail, history in `public.owner_briefs`, dead-man after 26h without an ok run)
- Platform Uso & Custos (`/api/admin/usage/{dev,machine,jobs,fx}`, page `/admin/uso`, platform admins only): dev usage evaluation per window -- Claude Code tokens / API-equivalent cost / chars, OS and job telemetry from the `dev_telemetry_*` tables (migration 097) -- kept apart from `ai_usage` and the credit wallet; `/api/admin/llm-usage` adds per-agent / per-session / attribution breakdowns and `agent_key` / `conversation_id` filters
- AI call pipeline (migration 116): `ai_usage` carries `trace_id` / `span_id` / `parent_span_id` / `latency_ms` / `prompt_version` (an LLM-call row is its trace span); `ai_trace_spans` holds tool / guardrail / internal spans (service-role only); view `ai_trace_timeline` joins both; function `ai_spend_window()` feeds the seed per-surface spend guard and view `ai_spend_24h_by_surface` is the report to choose its limits from (`KNOWLEDGE-BASE/CONTEXT/PATTERNS/ai/ai-engineering-canon.md` §6, §8)
- Platform AI usage & cost (`/api/admin/usage/ai/{sources,usage,cost,spend,deliveries,rate-limits}`, `app/routers/admin_ai_usage.py` + `app/services/ai_usage/`, platform admins only; migration 112, contract `products/core/docs/ai-usage-contract.md`): two sources never summed -- `anthropic` (Admin usage/cost analytics synced by the `anthropic_usage_snapshot` scheduler job with `ANTHROPIC_ADMIN_API_KEY`; unavailable on an Individual Org) and `ledger` (`dev_telemetry_claude` + `dev_deliveries`)
- User authentication and session handling (one cross-tab-locked refresh, `refreshCoreSession`; inactivity expiry ends only core's session via `POST /api/auth/logout?scope=local`, the "Sair" button ends every session)
- SSO token exchange for product access
- Stripe billing and subscription management
- User WhatsApp number (`public.noctus_users.telefone`, migration 096, E.164): set by the user at `/settings` (field "WhatsApp"), `PATCH /api/auth/profile {telefone}` normalizes via `noctusai_lib.primitives.phone` (`""` clears, invalid → 422), returned by `/api/auth/me` and the admin user list. The SINGLE source of truth — products (social-wiring Julia report destination, agents evaluation allow-list) store a user id and resolve the phone with `table_reads.resolve_user_phones`
- Prepaid AI credit wallet (migration 093; page `/org-settings/creditos` "Créditos e uso", admin `/admin/creditos`): per-org balance in credits (default R$ 0,01 each) debited every minute from `ai_usage` (`core_credits_debit` job), usage shown org → product → feature in credits, R$ and tokens; top-ups by PIX/boleto/card on the existing Asaas/Stripe gateway (`POST /api/credits/purchase`, credited by the verified paid webhook); admin grants in credits or US$ through the same ledger path; modes `prepaid` / `postpaid_trusted` / `byok`. A prepaid org at/below its overdraft floor is refused (HTTP 402) by the seed `enforce_budget` guard, fail-closed
- M2M API tokens (`/admin/tokens`, migration 099, platform admins): mint / rotate / revoke `noc_` tokens (legacy `pk_` accepted until the cutoff) with scopes from a server allow-list (`transcription:*`, `reminders:*`), optional no-expiry, `last_used_at`, and a `noc-agent` service account; the platform switch "MFA para gerar tokens" (`platform_settings.exigir_mfa_para_tokens`) ships OFF -- when turned on an unmet MFA is refused by name (`mfa_required`)
- NoctusAI's own sales funnel (`/api/admin/funnel`, page `/admin/funil` under CRM, migration 107, platform admins only): every `website_leads` row IS a card of the seed funnel organ (a trigger places each new lead in the first stage); stages are editable and start Novo → Contatado → Qualificado → Proposta; won / lost / archived are statuses (lost reason from a coded list + "Outro"); value is one-off + monthly. Gates: Contatado needs a WhatsApp or e-mail, Qualificado a responsável, Proposta an offer with value. `NOC-REMEDIATE[core-funnel-ganho-bridge]`: winning a card does not yet send the Stripe link / create receivables
- Product licensing and provisioning
- Admin dashboard with platform-wide controls
- Admin panel is NOT RENDERED for anyone but a server-confirmed platform admin (`/api/auth/me` `user.role === 'admin'`; `marketing` = website only): the sidebar (seed `Sidebar` organ over module groups CRM, ERP, CMS, Integrações, Configurações, Operação, Modelos + standalone Painel), routes and pages live in a code-split chunk (`frontend/src/admin/`) loaded by `pages/CatchAll`; anyone else gets the same NotFound as an unknown path. One `canReach(role, href)` predicate registers routes and prunes the nav. See `KNOWLEDGE-BASE/CONTEXT/frontend/01-CORE.md`
- 7-role hierarchy (owner, admin, manager, member, viewer, dev, test)
- Team invitations and role assignment
- Notification system (platform-wide): bell on every authenticated page, live neutral pop-ups for new operational notices (seed shell; `components/NotificationBell.tsx` exports the hooks + `openInProduct` it feeds)
