# Social Wiring — MASTER-PROMPT

> Authoritative development guide for the `social-wiring` product (SW).

## Purpose

SW is noc's **real-estate operations hub**: inbound leads (portals, Meta Ads, WhatsApp), the
sales funnel and per-lead cards, properties / owners / condominiums, contracts, matrículas and
certidões, marketing (Meta, Instagram, email, CoreStudio), and the **WhatsApp transport and CRM
side of Julia**, the SDR agent. It started as a media/YouTube/scheduling CMS and absorbed
`mailing`, `imobi-scheduling` and several others; those modules still live here.

**Division of labour with `agents`.** Julia's brain (prompt, tool loop, LLM keys, versions) is
hosted in the `agents` product and consumed over its `/api/channels/*` API. SW owns what
surrounds the turn: webhook intake, the per-chat pause/handoff policy, rate limits, the single
outbound gate, the CRM (contatos, interações, eventos, leads, cards), knowledge/questions the
org configures, follow-ups, notifications and reports. SW never calls an LLM for a Julia turn.

## Julia (renamed from "Lais" on 2026-10-19)

"Lais" is Lastro's product (reverse-engineered in a private study outside git, kept as the vendor
study). Everything we built under that name is Julia: code `julia_*`, tables `julia_*`, API
`/api/julia/*`, pages `/julia/*`, nav group "Julia".

- **Backend**: `app/routers/julia_*_router.py` (agente, conversas, conhecimento, perguntas, visitas, reengajamento, notificacoes, envio, equipes, cloud/modelos/disparos, captacao, credito, avaliacoes, relatorios, painel, ferramentas), `app/services/julia_*` (one service per area), `app/clients/agents.py` (the agents HTTP client; `AgentsClient` / `FakeAgentsClient`).
- **Turn** (julia-v2: Julia is hosted in agents, SW consumes her via the API only): WAHA webhook → `julia_lead_turn_service` (debounce, limits; NO local pause gate -- `whatsapp_chats.agente_pausado` is a display mirror) → agents `POST /api/channels/turns` with `agent_key="julia"`, the lead ref and a data-only `contexto` → agents answers a `status`: a served one sends the bubbles and its typed actions (`HandoffAction`, `JuliaAction`: `lead_pronto`, `intencao_visita`, …) are applied idempotently by `julia_acoes_service`; every other status, an error or a timeout sends nothing (fail closed). Thread API (append without a turn, per-conversation pause via `PATCH participantes`, hand-offs, consent, LGPD delete-by-lead, controls read, computed qualification) is `AgentsClient`; the SW side is `julia_thread_service` / `julia_espelho_service`.
- **Business specs (Julia-line S9)**: **Julia > Especificações** (`julia_especificacoes_router`, org admin) is a faithful proxy of agents' `GET|PUT /api/channels/agents/julia/specs` through `clients/agents.py` (`especificacoes` / `salvar_especificacoes`) with the org's `api_key:agents` credential. SW stores nothing and validates nothing: agents' 200 (`declaradas`, `valores`, `faltando`, `invalidas`, `modo_validacao`) and 422 (`code`, `detail`, `violacoes[{chave,codigo,motivo,mensagem}]`) bodies pass through unchanged for the per-field messages. The acting user (id + name + e-mail) is filled by the route from the authenticated session and sent as `ator` (a body `ator` is refused); agents shows it back as `valores[].updated_by_nome` ("alterado por X em Y"). No credential → 409 `agente_nao_conectado`; agents refusing the token → 502 `agents_token_invalido`; down → 502 `agents_indisponivel`.

- **Go-live hardening (SW, migration 321)**: every MUTATION of a WhatsApp line (PATCH, DELETE, start/restart/logout/recover, `/webhook`) is org-admin only (`require_org_admin_for`; a plain member still reads the inbox and sends a reply). Migration 321 also revokes browser SELECT on `webhook_token` and `encrypted_api_key` (column-level GRANT for the rest; every SW reader uses the service-role client). Error bodies are generic (no `{exc}` echo; details go to the log by type). Webhook (`whatsapp_router._process_waha_body`): an envelope whose `session` is not the line's `session_name` is refused; with the HMAC secret set, a message event whose `timestamp` (the envelope's, else the message's) is older than 300 s or more than 60 s in the future is refused (`timestamp_antigo` / `timestamp_futuro` / `timestamp_ausente`); an empty message id is dropped on a Julia line (`id_vazio`); every refusal is a logged 200 no-op with its reason, an unsigned/badly signed call keeps its strict 401. `status@broadcast`, `@broadcast` and `@newsletter` (seed `noctusai_lib.integrations.whatsapp.inbox.ingest.is_non_conversation_jid`, the ONE classifier) are dropped before storage and `julia.is_group_chat` treats them like a group (never routed, no AI call). Forwarded messages: `schemas.whatsapp.mensagem_encaminhada` reads WAHA's forwarded flag per engine and a forwarded lead message in the agents turn carries `encaminhada: true` (omitted when false, so an agents build without the field keeps accepting every ordinary turn; agents must accept it before a forwarded message is sent). ## Contract parties (matrícula-driven)

**Contract RG is optional, CPF is mandatory (julia-v3, 2026-11-03).** An absent RG omits the RG clause and the party is qualified by CPF alone; an incomplete RG only warns. Under a signature name the document line is CPF and/or RG (`frases.documentos_assinatura`). `carregador.identidade_nao_verificada` blocks generation while a CPF/RG came from a WhatsApp document nobody confirmed.

**Contract parties follow the matrícula.** A vendedor typed `proprietário` who is not among the matrícula's current owners (adquirentes of the last transfer act, `titulo_service.titularidade_atual`) blocks generation with `VENDEDOR_NAO_PROPRIETARIO` and the readiness names the right papel (cônjuge of an owner → anuente; doador in the chain → anuente); owners unknown checks nothing. When the sellers hold the imóvel by **doação** (adiantamento de legítima) the doadores are `anuente`s worded as such (`derivacao.doador_anuente`, no extra column); a spouse-anuente keeps its own wording. A CNH-only RG completes itself from the matrícula averbação (`card_hub/rg_matricula_service.py`, `rg_origem='matricula_averbacao'`), nacionalidade is inflected by gênero, and a certidão de casamento hands the linked cônjuge the couple's estado civil/regime/data.
