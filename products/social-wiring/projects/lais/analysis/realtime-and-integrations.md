# Realtime, auth and integrations

## 1. EventHub websockets (`wss://eventhub.lastro.services`)
Three independent sockets; all authenticate with **query-string** `?token=<Keycloak access token>&agencyId=<reaId>` (token redacted in logs via `/token=[^&]+/`). JWT `exp` checked client-side before connecting; 10 s connect timeout; exp. backoff reconnect (max 30 s + jitter).

| socket | URL | client → server | server → client events (`{event, data}`) | consumers |
|---|---|---|---|---|
| chats | `wss://eventhub.lastro.services/ws/chats?token=…&agencyId=…` (C chats page `socketUrl:"".concat(_,"/ws/chats")`; 3b4451b3 `${a}?token=${this.accessToken}&agencyId=${this.agencyId}`) | `{event:"join",data:{chatId}}`, `{event:"leave",data:{chatId}}` (C 3b4451b3) | `chat_updated`, `chat_list_item_updated`, `chat_list_update`, `chat_suspended` → chat-list handlers; `new_message`; `feed_sync_completed`; `tag_definition_updated` (data = tag def); `typing` (data `{chatId, side:"user"|"assistant"}` — only those two sides forwarded); `message_status_updated` (data = message status) | /chats, /history, chat drawer (9654) |
| notifications | `…/ws/notifications?token=…&agencyId=…` (C 5435 package `@lastro/web-notifications`) | — | `notification:created` (`data.type` = notification-event type) | layout `WebNotificationsProvider` (C layout `socketUrl:"wss://eventhub.lastro.services"`, invalidates `notification.all` queries on notification/reconnect); favicon badge counter; browser notifications behind flag `browser-notifications-front` |
| properties | `…/ws/properties?token=…&agencyId=…` (C 9654) | — | `feed_sync_completed` (`data.status`) | properties/ads feed sync (after `POST /web/ads/xml/sync`) |
Chat-list update reason enum (C 3b4451b3): `unread, user_assigned, team_assigned, archived, chats_template, tags_updated, kanban_move, pinned`.
Chat-room membership: the client joins a single chat room at a time (`connection.currentChatId`) to receive `new_message`/`typing` for it (I).
Logs redact `data.lead.phoneNumber` for non-typing events (C `sanitizeForLogs`) ⇒ chat events carry the lead object incl. phone (I).

## 2. Auth: Keycloak + NextAuth (+ BFF)
- IdP: Keycloak at `https://sso.lastro.services`, realm **`lastro-prod`** (C 6844 `o="https://sso.lastro.services",a="lastro-prod"`); sandbox default `lastro-sandbox`; client id **`casa-da-lais`** (confidential: client secret server-side) — C 5138 env schema.
- NextAuth (server, `/api/auth/*`): Keycloak provider, scope `openid email profile`; JWT session strategy, maxAge 30 d; pages `signIn:/auth/signin`, `error:/auth/error`; cookies `__Secure-next-auth.session-token` (when prod & no cookie domain) or `next-auth.session-token` with domain `NEXTAUTH_COOKIE_DOMAIN` (e.g. `.casa.lais.ai`), `__Host-next-auth.csrf-token`, `next-auth.state`, `next-auth.pkce.code_verifier` (15 min). C 5138.
- JWT callback stores `{sub,name,email,accessToken,idToken,refreshToken,expiresAt,roles}`; when expired, refresh: `POST {KEYCLOAK_ISSUER}/protocol/openid-connect/token` form `client_id, client_secret, grant_type=refresh_token, refresh_token` → error `RefreshAccessTokenError`. Session exposes `accessToken, refreshToken, idToken, roles, error` to the browser (C `handleSessionCallback`).
- Browser API calls: bearer = session `accessToken` (cached; `getAuthToken`), plus `x-agency-id` (selected REA). Bridge iframes take the token from `window.top.__laisAuth`.
- Logout: `DELETE https://bff.lastro.services/api/v1/auth/logout` with Bearer (C 5138) → NextAuth `signOut({redirect:false})` → `sessionStorage.post_logout_signal="1"` → redirect to `https://sso.lastro.services/realms/lastro-prod/protocol/openid-connect/logout` with `id_token_hint` (I: + post_logout_redirect_uri) (C 6844).
- /history alternative auth: **access code** ("Código de acesso" — "Compartilhe com colaboradores para que acessem links da Lais", C 7531) → `POST /api/access-code/validate`, `GET|DELETE /api/access-code/session`; env `KEYCLOAK_HISTORICO_*` = separate Keycloak client for these sessions (I); request option `preferHistoricoSession` (C 5138).
- Attendants: when flag `attendant-app-migration` is false, users whose REA role is `attendant` are redirected to `https://atendimento.casa.lais.ai` (separate attendant app) (C layout).
- Mobile app exists: "Casa da Lais" iOS id6749020881 + Google Play (C layout banner).

## 3. Facebook / Meta
- Meta Integration (`/configs_meta_integration`; visible only while flag `meta-integration-front` is **false** — true redirects to /configs, C): popup `https://www.facebook.com/v21.0/dialog/oauth?client_id=3958667614391745&redirect_uri=<origin>/facebook/callback&state=<32-byte hex>&response_type=code&config_id=1077486161187624` (Facebook Login for Business config id); `state` kept in `localStorage.fb_oauth_state`; `/facebook/callback` page posts `{type:"FB_OAUTH_CALLBACK", code|error, errorDescription}` to the opener (same-origin check, 5 min timeout) → `POST /web/facebook/callback {code}` → `{pages[]}` → user selects → `POST /web/facebook/connect/finalize {pageIds}` (C configs_meta_integration). Pages list, delete page ("Desconectar conta Meta" — "A Lais não rece[berá]…"), Lead Ads forms: list (`/forms`, `/forms/local`, `/forms/meta`), create, toggle active, field mapping (`/forms/:id/mapping {mappings}`), questions. Purpose: ingest Facebook/Instagram Lead Ads into Lais ("Conecte suas campanhas do Facebook e Instagram à Lais."). Scopes/app id: see routes.md Part B (U here).
- Smart campaigns (CAPI): Lais sends qualification signals (lead qualificado, visita agendada, resposta do cliente) to Meta Conversions API via pixel; onboarding states needs_oauth → awaiting_configuration → ready; per-campaign `capi` flag, CPL/CPQL metrics (C 95095 copy, mocks).
- Meta catalog + dynamic remarketing: listings pushed to a Meta catalog, product sets ("subsets") with filter grammar; system subsets "Remarketing Dinâmico Lais - Venda/Aluguel" (C mocks, 41415).

## 4. WhatsApp
- Lais runs on the **WhatsApp Business (Meta Cloud) API** (I: templates with `{{1}}` placeholders, 24 h window rules). Evidence: tooltip "Só é possível mandar mensagens livres em conversas durante às 24 horas que sucedem a última mensagem do cliente. Para retomar o contato, envie um modelo de mensagem." and "Aguarde 24 horas da última mensagem de template para enviar a pr…" (C 3b4451b3); window states `window_open | window_closed | unauthorized | unauthorized_suspended`.
- Templates: `/web/templates` (available, categories, params, create, delete); new-conversation template send (`/web/chats/new/messages/human/template`). Template categories values: routes.md Part B.
- Message statuses `none | sent | delivered | read` (flag `message-status-checks`); forwarded labels "Encaminhada"/"Encaminhada com frequência"; media types image/audio/video/document ("Mensagem de voz"); media upload errors `MEDIA_001..006`.
- Broadcast warning: "Disparos grandes consomem mais mensagens e podem afetar a qualidade do seu número no WhatsApp." (C broadcasts).
- WhatsApp profile settings = Bubble `configs_whatsapp_profile` (not in bundle).
- Human messages optionally prefixed with sender name: agency setting `prefixHumanMessagesWithSenderName` (/configs_display_attendant_name, I).

## 8. AI-agent ("brain") configuration — what is knowable from this bundle
Native (field-level detail in routes.md fragments A/B):
- **Qualificação e Envio ao CRM** — the /configs card opens the **Bubble** page `configs_behavior`; Bubble in turn embeds the native `/configs_qualification` ("Envio de leads qualificados") as a drawer (C 28068 `let t="/configs_behavior"`; layout bare-embed list). The rules are stored as audience **user-profiles**: `POST/PATCH /web/audiences/user-profiles` body `{name, identifier:"", transactionType:"buy"|"rent"|"both", type:"filter"|"priority", active, fields:[{fieldName, operator:"filled"|"greater-than-or-equal"|"less-than-or-equal"|"between", value:{}|{value}|{min,max}}]}`. Groups OR'ed, criteria within a group AND'ed; base group "Comportamento" (`type:"filter"`, "Qualificado via inteligência da Lais") = let the AI judge; other groups `priority`. Criteria come from the agency's "Perguntas essenciais" (`GET /web/audiences/required-informations` → `{id, information, isNumeric, isCurrency}`), whose editor is Bubble `configs_behavior?type=questions`. When visits are enabled (`GET /web/visits/config`), "Visita — Pré-agendada via formulário da Lais" is a locked criterion. UI conditions: `selecionar` Selecionar condição, `a_partir_de` A partir de, `ate` Até, `de_ate` De - Até, `independente` Independentemente do valor.
- **Reengajamento automático** `/configs_reengage` — reminder (5–60 min) & final (1–24 h) delays; "réguas" (rules) per buy/rent with ≤3 attempts {delayValue, delayUnit days…, templateId}; templates lead_reengage(_short/_long/_brief_message); execution window "Das 8h às 20h" (C 2470).
- **Pré-agendamento de visita** `/configs_visits` — visit settings: mode unified/per-operation (`perOperation`), enabled, documentRequired, daysToOffer, minDaysToOffer, minHoursToOffer, weekly schedule slots (Mon–Sun, start/end, ≥1 h, no overlap, on grid) (C 1647, mocks).
- **Nome do atendente** `/configs_display_attendant_name` — `prefixHumanMessagesWithSenderName` (I).
- **Modelos de mensagem** `/configs_templates`, **Integrações Meta** `/configs_meta_integration`.
- Agency settings: `allowNotifications, useIptu, allowEnhanceAcquisitionLeads, prefixHumanMessagesWithSenderName, bankslipOccurrences, disableOnboardingTestLeadStep, overduePaymentSlipAlertDismissedAt`.
Bubble-only (fields NOT in bundle — must be mapped live): **Comportamento da Lais** (`configs_behavior`), **Meu negócio** (`configs_my_business`), **Perfil do WhatsApp** (`configs_whatsapp_profile`), **Endereço e IPTU dos imóveis** (`configs_property_info`).
Config menu labels (C configs): MY_BUSINESS Meu negócio · WHATSAPP_PROFILE Perfil do WhatsApp · META_INTEGRATION Integrações Meta · TEMPLATES Modelos de mensagem · VISITS Pré-agendamento de visita · QUALIFICATION Qualificação e Envio ao CRM · REENGAGE Reengajamento automático · PROPERTY_INFO Endereço e IPTU dos imóveis.
AI runtime signals visible to the UI: chat `suspended` (AI paused), typing indicator with side `assistant`, message side `assistant` vs `human` vs `user`, chat feedback like/dislike on AI answers.
