## Platform-scope amendment (2026-11-15, migration 351 / EST-2)

What changed, for the next review:

1. **Scope.** Profiles and videos are no longer owned by a client org: they are one platform-wide library (`cs_perfis_monitorados.org_id` and `cs_virais.org_id` are NULL for new rows). Orgs and brands only choose which library profiles they use (`cs_biblioteca_referencias`, still per brand). Members may no longer suggest profiles; only platform admins add them, by profile (synced) or by pasting one Instagram post link.
2. **New data category: Estruturas** (see Data categories). Derived from third-party public content; an auto-draft is created for every newly analysed video but is invisible and unusable until an admin publishes it.
3. **Ingestion org.** All scraping, transcription-lane use, classification LLM metering and cost ledger run under one org (the NoctusAI org; settings `corestudio_biblioteca_org_id` / `corestudio_biblioteca_user_id`). Unconfigured = a visible coded failure, never a silent skip.
4. **Opt-out cascade.** The opt-out purge now also erases the creator's Estruturas (FK cascade inside the single `cs_perfil_purgar` transaction); only content-free event rows remain (`cs_estrutura_eventos.excluida`, `cs_perfil_eventos.optout_purgado`). The registry blocks re-creation through every door: `POST /perfis`, `POST /virais/por-link`, the Estruturas import.
5. **Retention exemption.** See Retention. Open question for the owner / legal-advisor: whether keeping Estruturas after the source video's media expires is covered by the legitimate interest already balanced in the LIA (the Estruturas hold the creator's structural pattern and short notes about the video, not its media or voice).
6. **Audit.** Every admin write on a profile or video appends a `cs_perfil_eventos` row (append-only, content-free). **Since the owner decisions of 2026-11-15 the row keeps only the profile id: no handle**, so a purged profile's history cannot say who it was.
7. **Owner decisions of 2026-11-15 (FIX-1).** (a) 24-month-unused review: flag for admin review, never auto-archive. (b) Client orgs see handle + display name only, no photo. (c) A retained profile is minimised (photo and follower count dropped). (d) Security-review fixes: opt-out re-checked at import / job time and inside the creation RPC; transcripts and in-flight transcription jobs erased through the transcription organ on purge; scrubbed worker errors; sweep of stranded load documents.

## EST-5 amendment (2026-11-16): AI derivation of draft Estruturas

1. **Operation.** For each analysed library video (automatically after classification, or when a platform admin asks via `POST /estruturas/a-partir-do-viral`), the platform sends to the LLM sub-processor the video's caption (≤ 5 000 chars), transcript (≤ 12 000 chars; only the opening ≤ 1 500 chars when a blueprint exists) and the stored hook/blueprint (≤ 4 000 chars), after server-side removal of @mentions, e-mail addresses, phone numbers, URLs and the creator's handle and display name. No profile id, handle, name field, URL, image or org/user id is sent. The reply is an abstract structure (headline formula with [placeholders], objectives, typed blocks); it is stored as an admin-only `rascunho` (every field `ia_sugerido`) and reaches client orgs only if an admin publishes it.
2. **Sub-processor.** Anthropic, PBC (United States), pinned for registry key `estruturas.derivacao`; a vendor change requires a ROPA amendment first. Anthropic's commercial terms forbid training on customer content; API inputs/outputs are deleted by the vendor within 30 days (up to 2 years if flagged by its trust-and-safety systems). An opt-out purge cannot reach that vendor copy.
3. **International transfer (Art. 33; Res. CD/ANPD 19/2024).** Legal basis: legitimate interest (LIA). Mechanism: OPEN. Anthropic's DPA (effective 2025-02-24) offers EU SCCs/UK/Swiss addenda only, not the ANPD Annex II clauses; the EU adequacy decision does not cover the US. The derivation does not run in production until the controller records a valid mechanism here (decision by a lawyer).
4. **Derived, not copied.** The server refuses (no draft is created) any output that reproduces 8+ consecutive words of the source, a 5-word run of the hook in the headline formula or block names, a formula without a [placeholder], or any @handle, #hashtag, the creator's handle or display name. Published auto-drafts are labelled as AI-generated from a public video, not text by the creator (the label is planned before switch-on).
5. **Retention.** Only `ativa` Estruturas exempt a profile from the 90-day purge. A `viral_auto` draft not published within `biblioteca_retencao_dias` is deleted (content-free event `rascunho_expirado`). Opt-out purges drafts with everything else.
6. **Kill switch.** `biblioteca_ingestao_habilitada` OFF (or unreadable) stops the derivation at both entry points before any read or model call; queued jobs wait.
